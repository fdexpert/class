1. 適合誰

寫給修習國立臺灣大學國家發展研究所「文本即數據：社會科學研究的計算方法」（115-1）而完全沒寫過 R 的研究生。你可能用過 SPSS、Stata，或只用過 Excel，甚至完全沒碰過任何程式語言——都沒關係，這份教材從「什麼是 Console」開始講。

如果你有 Python 經驗，第二篇可以跳著讀，但請不要跳過第三章的 Project 工作流，那是 R 社群和 Python 習慣差最多的地方。

2. 為什麼需要這份教材

課綱的「先備知識」寫得很直接：具備 R 使用經驗與基本程式設計能力，能自在執行一些 Python 程式碼，能自在使用 RStudio 或 Positron。第 1 週不需要安裝任何軟體、也沒有程式練習，環境設定指南會在第 2 週前提供——但第 2 週的 Lab 就要一口氣完成安裝套件、建立專案、設定 GitHub Desktop、複製課程儲存庫、還要在 Overleaf 編譯出一份 LaTeX PDF。到了第 4 週，就直接用 quanteda 從語料庫做到 token 與 DFM。

換句話說，這門課把 R 當成已經會的工具，把課堂時間留給方法論。工具不熟的人會在第 3 到第 5 週之間迅速掉隊——不是因為聽不懂主題模型，而是因為卡在讀不進檔案、中文變亂碼、套件裝不起來這些跟課程內容無關的事。這份教材就是要把那些事提前解決掉。

▍這份教材不教什麼

不教統計、不教文本分析方法本身、不教主題模型怎麼解讀——那些是課堂的事。這裡只處理「手」的問題：怎麼把想法變成能跑的程式碼，怎麼把結果變成可以交出去的檔案。

5. 貫穿範例：立法院書面質詢

全課程用同一份真實資料串起來：立法院第 11 屆書面質詢 162 筆，取自立法院開放資料 API，涵蓋第 1 至第 3 會期、28 位委員，每筆有「事由」（一句話摘要）與「說明」（完整質詢內容，平均 617 字）。

選這份資料有三個理由。第一，它是中文，你會真實遇到中文斷詞的問題，而不是拿英文範例練完、上課換中文就傻眼。第二，它是政治文本，正好是課程第 12 週建議的期末題目方向之一（台灣立法行為、立法演說分析）。第三，它不乾淨——原始 PDF 排版在漢字之間塞了空白，會出現「造成許多觀光客抱怨臺灣政策之反覆與延宕」被拆成「造 成 許 多 觀 光 客」的狀況。真實資料就長這樣，我們會在第三篇正面處理它。

▍關於 legisTaiwan 套件

授課教師維護的 legisTaiwan 套件原本是抓這份資料最方便的方式，但 2026-09-17 實測，它的 get_ly_interpellations() 與 get_ly_legislators_by_term() 都回傳 HTTP 404，套件內部呼叫的端點與現行 API 已不一致。底層 API（ly.govapi.tw/v2）本身正常。因此本教材的取材腳本改為直接呼叫 API。這件事本身就是很好的一課：套件會壞，API 會變，你要有能力判斷是誰壞了。第十章會教你怎麼做這個判斷。

R、RStudio、Quarto、GitHub、Overleaf：工具的分工

本章目標：搞懂這幾個工具各自負責什麼、哪一個才是真正的交件窗口，以後看到錯誤訊息也才知道該去哪裡找。

為什麼要先講這個R 是引擎RStudio 是駕駛艙Quarto 是排版廠GitHub 的角色Overleaf速查對照表動手練習本章小結

1. 為什麼要先講這個

新手最常見的困惑不是「這行程式碼怎麼寫」，而是「我到底該在哪裡打這行字」。有人在終端機裡打 R 的指令，有人在 R 的 Console 裡打 brew install，然後對著錯誤訊息發呆。這些困惑的根源都一樣：分不清楚這幾個東西的界線。

先把界線畫清楚，後面十八章都會輕鬆很多。

工具的分工。實線是你主動觸發的動作，虛線是自動回流的結果。注意：套件掛在 R 底下，不是掛在 RStudio 底下——換 IDE 不用重裝套件，換 R 版本才要。

2. R 是引擎

R 是一個程式語言，也是執行這個語言的程式。它本身沒有漂亮的介面——你可以在終端機打 R 直接啟動它，看到的就是一個 > 提示符號，你打指令、它算給你看，如此而已。

terminal
R --version
# R version 4.6.1 (2026-06-24) -- "Great Square Root"

所有真正的運算——讀檔案、算詞頻、跑主題模型——都是 R 在做。套件（package）也是裝在 R 裡面，不是裝在 RStudio 裡面。這個觀念很重要：你換 IDE，套件不用重裝；你換 R 版本，套件要重裝。

▍你的 R 裝在哪

macOS 上官方版 R 裝在 /Library/Frameworks/R.framework/，指令在 /usr/local/bin/R。套件裝在 /Library/Frameworks/R.framework/Versions/4.6/Resources/library。這條路徑之後排查問題時會用到。

3. RStudio 是駕駛艙

RStudio 是一個 IDE（整合開發環境）。它自己不會算任何東西，它做的事情是：幫你編輯程式碼、把你的程式碼送去給 R 執行、把 R 吐回來的結果排版顯示、順便管理你的檔案、畫圖、查說明文件。

用車來比喻：R 是引擎，RStudio 是方向盤、儀表板和音響。沒有 RStudio 你還是能開（用終端機跑 R），但很難開。沒有 R，RStudio 就是一個打不著火的空殼——事實上 RStudio 啟動時如果找不到 R，會直接跳錯誤。

▍一個立刻能用的判斷法

當你看到錯誤訊息時，先問：這是 R 說的，還是 RStudio 說的？Error in library(quanteda) : there is no package called 'quanteda' 是 R 說的，跟 RStudio 無關，重裝 RStudio 不會有幫助。而「Console 字太小」「面板不見了」則是 RStudio 的事，跟 R 無關。

4. Quarto 是排版廠

Quarto 是一個獨立的命令列工具（不是 R 套件），它把「文字 + 程式碼 + 程式碼跑出來的結果」組合成一份完整文件，輸出成 PDF、HTML 或 Word。

Quarto 一次解決兩件事——你的報告和你的程式碼是同一份檔案，改了數據重新 render，表格和圖自己更新，不會出現「論文裡的數字跟程式碼跑出來的不一樣」這種學術災難。

▍但這門課的計分文件不能用 Quarto

2026-09-17 版課綱把這件事講得很死：書面作業與海報必須使用課程提供的 LaTeX 範本，透過各自獨立的共用 Overleaf 專案繳交，並開放授課教師 Editor（可編輯）權限。課綱原文明寫「分析筆記本可使用 Quarto，但 Quarto 不能取代 LaTeX，作為計分書面作業或海報的撰寫格式」。

所以兩者分工是：Quarto 用來做你自己的分析筆記本（跑程式、看結果、留紀錄），Overleaf 上的 LaTeX 用來寫要交出去的東西（摘要、期中研究設計、海報、期末論文）。Quarto 仍然值得學，它是你私下工作的主力，只是別拿它當繳交格式。

Quarto 底下還串了兩個工具：Pandoc 負責格式轉換，LaTeX（我們裝的是 TinyTeX）負責排出 PDF。你不用直接操作它們，但出錯時錯誤訊息可能來自它們，知道有這層會少走很多冤枉路。

5. GitHub 是教材來源，Overleaf 才是交件窗口

Git 是版本控制系統，GitHub 是把 Git 儲存庫放在網路上的服務。在這門課，GitHub 的角色是取得東西而不是交出東西：課綱寫明「GitHub 是課程教材與程式碼的主要來源」，教材另外同步鏡像到 NTU COOL 供公告與討論。第 2 週的 Lab 就要你設定 GitHub Desktop 並複製（clone）課程儲存庫。

好消息是課綱明說「不需要 Git 經驗」，你會用 GitHub Desktop，一個圖形介面工具，不用背指令。第 16 章會完整走一遍。

GitHub 在期末還有一個角色：期末論文要附一個 GitHub 或 CodeOcean 的可重現程式碼儲存庫。所以你整學期的程式碼怎麼組織，到期末會直接變成交出去的東西的一部分——這是第 3 章那些資料夾紀律的最終理由。

這裡先建立一個觀念：Git 管的是程式碼和文字檔的歷史，不是拿來存資料的雲端硬碟。把幾百 MB 的語料推上 GitHub 是新手最常犯的錯之一，第 16 章會教你用 .gitignore 擋掉。

6. Overleaf：真正的交件窗口

Overleaf 是線上的 LaTeX 編輯器，瀏覽器裡就能寫、即時編譯出 PDF、多人可同時編輯。這門課四項計分繳交——研究論文摘要、期中研究設計報告、期末海報、期末研究論文——全部走 Overleaf。

兩個容易出錯的細節：每一項作業用各自獨立的 Overleaf 專案，不要全部塞在同一個；權限必須開到 Editor（可編輯），只給 View（僅檢視）不算繳交。課綱把這兩點都明確寫出來，代表過去有人踩過。

▍第 2 週就會用到

第 2 週的 Lab 要求你在 Overleaf 建立一份簡短的 LaTeX 文件、編譯成 PDF、並邀請授課教師取得 Editor 權限。建議現在就去 overleaf.com 註冊一個免費帳號，用學校信箱註冊，之後要加入課程專案比較單純。實際的 LaTeX 撰寫會在第 15 章談。

▍Windows 差異

路徑不同：R 通常在 C:\Program Files\R\R-4.6.1\，套件預設裝在使用者資料夾 C:\Users\你的名字\AppData\Local\R\win-library\4.6。另外 Windows 需要額外安裝 Rtools（cran.r-project.org/bin/windows/Rtools）才能編譯需要 C++ 的套件；macOS 的對應物是 Xcode Command Line Tools。本課有幾個套件（如 jiebaR）會用到編譯，沒裝 Rtools 會失敗。

8. 動手練習

  1. 打開「終端機」（macOS 內建，在 應用程式 → 工具程式；Windows 用 PowerShell），輸入 R --version、quarto --version，確認兩個版本號都印得出來。
  2. 在同一個終端機輸入 R 進入 R 的 Console，打 1 + 1 按 Enter，看到 [1] 2。然後打 q()、再打 n 離開。你剛剛用的就是「沒有 RStudio 的 R」。
  3. 打開 RStudio，在它的 Console 裡一樣打 1 + 1。對照一下：同一個引擎，不同的駕駛艙。
  4. 在 RStudio 的 Console 打 R.home()，看看它指到的路徑是不是上面提過的那個。

9. 本章小結

  • R 是引擎，負責運算，套件裝在 R 裡；RStudio 是駕駛艙，負責讓你舒服地操作 R。
  • Quarto 是獨立工具，適合做自己的分析筆記本；但課綱明定它不能當計分書面作業或海報的格式。

四大窗格Console 與 Script 的差別執行快捷鍵Environment 面板Help 與 Files六項必改設定動手練習本章小結

1. 四大窗格

第一次打開 RStudio 只會看到三個窗格，左上角的 Source（編輯器）要等你開啟或新建檔案才會出現。下圖是四個窗格的相對位置，實際畫面請對照本節的示範影片。

RStudio 預設的四窗格配置示意（非實際截圖）。藍框的兩格是你最常互動的。窗格位置可在 Settings → Pane Layout 自由調換，因此同學的畫面未必與此圖一致。

左下角窗格還有一個常被忽略的分頁：Terminal。它是真正的系統終端機（macOS 上是 zsh），跟 Console 完全不同——Console 吃 R 語言，Terminal 吃 shell 指令。課綱的先備知識裡「會用終端機」指的就是這個。你不用精通，但要知道 brew install、git status 這類指令屬於 Terminal，不屬於 Console。

2. Console 與 Script 的差別（本章最重要）

這是新手最容易混淆、也最影響學習效率的一件事。

Console 適合試探：想知道 nchar("測試") 回傳什麼，直接在 Console 打，看到答案，丟掉。它是草稿紙。

Script（.R 檔）適合累積：你的分析流程——讀檔、清理、斷詞、建 dfm——要寫在 Script 裡，存檔，明天打開還在，下週改一個參數重跑一次。它是你的作品。

▍新手最常犯的錯

整個分析流程都打在 Console 裡，跑出漂亮結果，然後關掉 RStudio。隔天要重現，全部消失。期末論文要附可重現的程式碼儲存庫，Console 裡的東西交不出去。從第一天就養成習慣：凡是會想再跑第二次的，都寫進 Script。

新建 Script 的方式：選單 File → New File → R Script，或直接按 Cmd+Shift+N。

在 Script 裡寫好程式碼後，要把它「送」去 Console 執行。用滑鼠複製貼上是可以，但你一天會做幾百次，請從第一天就用鍵盤。

右上角 Environment 列出目前記憶體裡所有的物件。你執行 x <- 5 之後，這裡就會出現一列 x 5。讀資料進來之後，會出現類似 d 162 obs. of 8 variables——這是快速確認「我到底讀進了幾筆資料」最方便的地方。

資料框旁邊有個表格圖示，點下去會用試算表的樣子打開資料，適合肉眼檢查。也可以在 Console 打 View(d) 達到同樣效果。

面板上方那把掃帚圖示會清空所有物件（等同 rm(list = ls())）。這是好習慣的一部分：如果你的 Script 只有在「清空環境後從頭跑」才會成功，它才是真的可重現。

5. Help 與 Files

在 Console 打問號加函數名稱，說明文件會出現在右下角 Help 面板。

R 的說明文件格式固定：Description（做什麼）、Usage（怎麼呼叫）、Arguments（每個參數的意思）、Value（回傳什麼）、Examples（可以直接複製執行的範例）。新手直接跳到最下面的 Examples 往往最快。

6. 六項必改設定

打開設定：macOS 是選單 RStudio → Settings…（舊版顯示為 Preferences），Windows 是 Tools → Global Options…。以下六項請在上課前改好，每一項都會實際影響你這學期的順暢度。

(1) 關閉工作區自動儲存 — General → Basic

把 Restore .RData into workspace at startup 的勾取消，並把 Save workspace to .RData on exit 設為 Never。

理由：預設行為會在你關閉 RStudio 時把所有變數存下來、下次開啟時還原。聽起來貼心，實際上是可重現性的頭號殺手——你的 Script 會依賴一個「上次殘留在記憶體裡、但程式碼裡根本沒有」的物件，自己跑得很順，助教跑就報錯。關掉它，強迫自己的 Script 完整。

(2) 啟用原生管線 — Code → Editing

勾選 Use native pipe operator, |> (requires R 4.1+)。

理由：這樣 Cmd+Shift+M 插入的會是 R 內建的 |> 而不是 magrittr 的 %>%。兩者在本課用途上幾乎等價，但 |> 是語言內建、不依賴套件，教材全程使用它。

(3) 開啟軟換行 — Code → Editing

勾選 Soft-wrap R source files。

理由：質詢文本一筆動輒六百字，沒有軟換行時你得一路往右捲。

(4) 確認編碼為 UTF-8 — Code → Saving

在 Default text encoding 按 Change… 選 UTF-8。

理由：這是中文資料的生死線。macOS 的預設通常已經是 UTF-8，但請親眼確認一次。編碼設錯的症狀是中文變成 \u5b78 或一堆問號，而且往往在你已經做了一堆分析之後才發現。

(5) 打開診斷提示 — Code → Diagnostics

勾選 Show diagnostics for R 以及 Warn if variable used has no definition in scope。

理由：RStudio 會在你打錯變數名或少一個括號時，在行號旁邊畫紅色驚嘆號。對零基礎的人來說，這能攔掉一半以上的低級錯誤。

(6) 顯示行號與空白 — Code → Display

勾選 Show line numbers（通常預設已開）與 Show whitespace characters。

理由：行號是你跟別人討論程式碼的座標；而顯示空白字元，在處理「被 沒 收」這種漢字間夾空白的髒資料時，能讓你直接看見問題。

▍順手可調

Appearance 分頁可以改主題與字體。中文顯示建議挑等寬中文字體避免對不齊。這項純屬舒適度，不影響正確性。

▍Windows 差異

設定入口是 Tools → Global Options…，沒有 macOS 的 RStudio → Settings 路徑。所有快捷鍵把 Cmd 換成 Ctrl。另外 Windows 的預設編碼可能不是 UTF-8，第 (4) 項對 Windows 使用者特別關鍵，務必手動確認。

Project 工作流與檔案結構

本章目標：學會用 RStudio Project 管理這門課的所有檔案，並徹底戒掉 setwd()。

本頁章節
工作目錄是什麼為什麼不要用 setwd()建立你的課程 Project資料夾結構here 套件動手練習本章小結

1. 工作目錄是什麼

R 在任何時刻都「站在」某個資料夾裡，那個資料夾叫工作目錄（working directory）。當你寫 read_csv("質詢.csv")，R 就是去工作目錄裡找這個檔名。找不到就報錯：

R Console
getwd()   # 我現在站在哪裡
list.files()  # 這個資料夾裡有什麼

新手 90% 的「檔案讀不進來」都是這個問題：R 站的位置跟你以為的不一樣。getwd() 和 list.files() 這兩行是排查第一步，請記起來。

2. 為什麼不要用 setwd()

網路上的舊教學會教你在 Script 開頭寫：

R · 請不要這樣做
setwd("/Users/yourname/Documents/text-as-data/data")   # macOS
setwd("C:/Users/yourname/Documents/text-as-data/data") # Windows

這行在你的電腦上完全正常，但它讓你的程式碼只能在你的電腦上跑。助教拿到你的作業，第一行就失敗，因為他的電腦裡沒有 /Users/yourname/ 這個路徑。這門課的期末論文要附 GitHub 或 CodeOcean 的可重現儲存庫，setwd() 等於在可重現性上自己開一槍。

正確做法是使用 RStudio Project：當你透過 .Rproj 檔開啟專案時，RStudio 自動把工作目錄設在專案資料夾。你的程式碼裡只出現相對路徑（data/質詢.csv），誰拿到都能跑。

3. 建立你的課程 Project

選單 File → New Project… → New Directory → New Project，資料夾名稱建議 text-as-data-lab，位置放在你習慣的地方。

建好之後你會發現三件事：RStudio 重新啟動了一次、右上角出現專案名稱、資料夾裡多了一個 text-as-data-lab.Rproj 檔案。以後開這門課的東西，就是雙擊那個 .Rproj 檔，而不是單獨打開某個 .R 檔。

▍.Rproj 檔裡有什麼

它是純文字檔，記錄這個專案的設定（編碼、縮排、是否還原 workspace 等）。你不需要編輯它，但它會被 Git 一起管理，讓協作者拿到同樣的專案設定。

確認一下：專案開啟後在 Console 打 getwd()，回傳的應該正是專案資料夾。

5. here 套件

專案內的相對路徑已經解決了大部分問題，但有一個例外：Quarto 報告放在 report/ 子資料夾裡，render 時的工作目錄是該 .qmd 所在的資料夾，於是 data/質詢.csv 就找不到了。

here 套件解決這件事——它永遠從專案根目錄算起，不管你的檔案放多深。

R
library(here)
here()                       # 專案根目錄在哪
here("data", "質詢.csv")     # 組出完整路徑，跨作業系統通用
# 讀檔時這樣寫：
# d <- readr::read_csv(here("data", "質詢.csv"))

注意 here("data", "質詢.csv") 用逗號分隔而不是自己拼斜線。這是刻意的：macOS 用 /、Windows 用 \，交給 here() 處理，你的程式碼就跨平台。

▍Windows 差異

Windows 路徑用反斜線 \，但在 R 字串裡 \ 是逃脫字元，必須寫成 \\ 或改用 /。這是 Windows 使用者的經典陷阱，here() 正好幫你完全避開。

  2. 建立 data／R／output／report 四個資料夾。
  3. 把教材附的 立法院質詢_第11屆.csv 複製到 data/。
  4. 執行 library(here); here()，確認回傳的是專案根目錄而不是 data 資料夾。
  5. 在 R/ 建立 01-import.R，只寫兩行並存檔（先不用管 read_csv 的細節，第 6 章會講）：

  • R 永遠站在某個工作目錄裡；getwd() 與 list.files() 是檔案讀不到時的第一組排查指令。
  • setwd() 會讓程式碼只能在你的電腦上跑，與本課的可重現性要求直接衝突。
  • 用 .Rproj 開啟專案，工作目錄自動就位，程式碼裡只寫相對路徑。
  • data 只讀不改、output 全部可重新生成——這兩條紀律是期末可重現儲存庫的基礎。
  • 跨資料夾或跨平台時用 here() 組路徑。

套件管理

本章目標：分清楚 install 與 library、知道套件從哪裡來，並且能看懂三種常見的安裝失敗訊息。

本頁章節
install 與 library套件從哪裡來本課套件清單三種安裝失敗函數名稱衝突renv動手練習本章小結

1. install 與 library：一次性 vs 每次都要

這是 R 新手第二常見的混淆（第一名是 Console 與 Script）。

install.packages("quanteda") 是下載安裝到硬碟，一台電腦做一次就好，之後永遠都在。

library(quanteda) 是把已安裝的套件載入這次的 R 工作階段，每次重開 R 都要再做一次。

用手機比喻：install 是去 App Store 下載，library 是點開那個 App。你不會每次用 App 都重新下載，但每次用都要點開。

▍寫進 Script 的規則

library() 寫在 Script 開頭，install.packages() 不要寫進 Script。理由：別人執行你的 Script 時，不該被強制安裝或升級套件。需要說明相依套件時，寫成註解或放在 README。

4. 三種安裝失敗訊息

套件裝不起來是必然會遇到的事。重點不是避免它，而是能讀懂訊息、判斷是哪一種問題。以下三種涵蓋你這學期八成的狀況，第三種是撰寫本教材時真實遇到的案例。

(A) 套件根本不存在或打錯字

R Console
Warning message:
package ‘quantedaa’ is not available for this version of R

先檢查拼字。拼字沒錯的話，表示 CRAN 上沒有適用你這個 R 版本的版本——可能是套件已下架、或作者尚未跟上新版 R。解法：去 CRAN 查該套件狀態，或改從 GitHub 安裝。

(B) 缺少系統相依

R Console
configure: error: libgit2 not found
ERROR: configuration failed for package ‘gert’

這不是 R 的問題，是作業系統缺少某個函式庫。關鍵字是 configure: error 加上一個聽起來像系統套件的名字。macOS 的解法是在終端機（不是 Console）執行 brew install libgit2，Windows 則多半是缺 Rtools。

(C) 編譯失敗：真實案例 jiebaR

2026-09-17 在 R 4.6.1 安裝中文斷詞套件 jiebaR 時，CRAN 回報「not available for this version of R」（情況 A），改從 GitHub 安裝後出現：

R Console
../inst/include/lib/limonp/StringUtil.hpp:88:60: error:
    no member named 'not1' in namespace 'std'
make: *** [RcppExports.o] Error 1
ERROR: compilation failed for package ‘jiebaR’

這是套件原始碼本身跟不上時代：std::not1 是 C++ 標準在 C++17 移除的功能，而 R 4.6 預設用 C++20 編譯。不是你的電腦壞了，也不是你裝錯，是上游套件的程式碼過時了。

可行的處理方式是下載原始碼、把那兩行改寫成現代的 lambda 寫法，再用 R CMD INSTALL 手動安裝——這也是前面表格裡「原始碼」那一列存在的理由。如果你遇到這個錯誤而不想自己改原始碼，替代方案是改用 Python 的 jieba（透過第 18 章的 reticulate），或先用 quanteda 內建的斷詞器處理中文，第 12 章會比較兩者差異。

▍這類問題會反覆出現

修補後的版本只存在於你自己的電腦上。日後重裝或更新同一個套件，會再撞到同一個錯，所以請把處理步驟記在專案的 README 或筆記裡。等到上游作者修正後，就能恢復用一般方式安裝。

▍為什麼要跟你講這麼細

因為這正是課綱第 10 章要教你的判斷力：看到一大片紅字時，能分辨「我打錯了」「我的系統缺東西」「這個套件本身壞了」。三種問題的解法完全不同，而新手最常見的反應是三種都用同一招——重裝——然後浪費一個下午。

5. 函數名稱衝突

載入套件時常看到這類訊息，它不是錯誤：

R Console
The following objects are masked from ‘package:stats’:
    filter, lag

意思是 dplyr 的 filter() 蓋掉了 stats 的 filter()。多數時候你要的正是後載入的那個，所以沒事。但當你確實需要指定時，用雙冒號：

R
dplyr::filter(d, 會期 == 1)   # 明確指定用 dplyr 的

套件::函數 這個寫法還有個好處：不用 library() 也能呼叫。教材裡偶爾出現的 readr::read_csv() 就是這個用法，目的是讓你一眼看出這個函數屬於哪個套件。

renv 為單一專案建立獨立的套件庫，並記錄每個套件的版本。別人拿到你的專案，執行 renv::restore() 就能重建一模一樣的套件環境。

R Console

renv::restore()   # 依 renv.lock 還原（別人拿到你的專案時用）

要不要現在用？建議先不要。renv 會讓每個專案各自安裝一份套件，你剛裝好的 41 個套件不會自動被新專案看到，對新手是額外的困惑來源。等到期末要交可重現儲存庫時，再回來用它，那時它的價值才真正顯現。這裡先讓你知道有這個東西，以及它解決什麼問題。

物件、向量與資料框

本章目標：學會把東西存進變數、認識四種你這學期會反覆遇到的資料型別，並理解 R 最重要的特性——向量化。

本頁章節
賦值四種型別向量與向量化取值NA資料框動手練習本章小結

1. 賦值：把東西存起來

R 用 <- 把右邊的東西存進左邊的名字。快捷鍵是 Alt+-（macOS 與 Windows 相同），它會自動補上前後空格。

R
x <- 10
y <- x * 3
c(x, y)
#> [1] 10 30

你也會看到有人用 = 賦值。兩者在多數情況下可互換，但 R 社群的慣例是 <-，而且 = 在函數呼叫裡另有意義（指定參數，例如 mean(x, na.rm = TRUE)），混用容易誤讀。這份教材一律用 <-。

▍那個 [1] 是什麼

R 印出結果時會在每行開頭標示「這行的第一個元素是整體的第幾個」。因為 R 眼中沒有單一數值，只有長度為 1 的向量——這是下一節的重點。

2. 四種型別

用 class() 問任何東西「你是什麼」。

R
class(10)                #> [1] "numeric"    數值
class("質詢")            #> [1] "character"  文字（一定要有引號）
class(TRUE)              #> [1] "logical"    邏輯值 TRUE / FALSE
class(factor("國民黨"))  #> [1] "factor"     類別（有固定的幾種可能值）
型別這門課的例子要注意什麼
numeric會期、字數、詞頻能做算術。整數與小數在 R 裡預設同屬 numeric。
character質詢全文、委員姓名一定要加引號。忘記加引號是新手最常見的錯誤之一，第 10 章會示範那個錯誤長什麼樣。
logical「這筆有沒有提到能源」只有 TRUE／FALSE／NA，全大寫、沒有引號。sum() 一個邏輯向量會得到 TRUE 的個數，很好用。
factor政黨、會期（當成類別看時）看起來像文字，其實是「有限選項」。跑統計模型時 R 會自動幫你轉成虛擬變數。新手階段可以先不主動製造 factor。

3. 向量與向量化（R 最重要的特性）

向量是「同一種型別的一串值」，用 c() 建立（c 代表 combine）。

R
字數 <- c(412, 631, 288, 905)

字數 * 2
#> [1]  824 1262  576 1810

mean(字數)   #> [1] 559
max(字數)    #> [1] 905
length(字數) #> [1] 4

請仔細看 字數 * 2：你沒有寫任何迴圈，R 自動把每個元素都乘以 2。這叫向量化，是 R 跟 Python、Java 這些語言最不一樣的地方。習慣寫迴圈的人來到 R，第一件要改的事就是「先想想能不能整個向量一起算」。

比較運算也是向量化的，結果是一個等長的邏輯向量：

R
字數 > 500
#> [1] FALSE  TRUE FALSE  TRUE

sum(字數 > 500)   # TRUE 算 1，所以這是「有幾筆超過 500 字」
#> [1] 2
▍這個觀念之後會一直出現

第 8 章判斷「哪些質詢提到能源」、第 13 章計算詞頻，骨子裡都是同一招：對一整欄做一次運算，得到一整欄結果。

還有一件事要小心：向量裡只能有一種型別。如果你混進文字，R 會安靜地把所有東西都轉成文字，不會報錯：

R
c(1, 2, "三")
#> [1] "1" "2" "三"     ← 數字被偷偷轉成文字了

這種「安靜地做了你沒預期的事」比報錯更危險，因為它要到很後面才會爆炸。習慣用 class() 確認。

4. 取值：中括號

R
字數[2]              #> [1] 631      第 2 個
字數[c(1, 3)]        #> [1] 412 288  第 1 和第 3 個
字數[字數 > 400]     #> [1] 412 631 905   用邏輯向量篩選

最後一種寫法值得多看兩眼：中括號裡放一個邏輯向量，R 會留下 TRUE 的位置。這就是 dplyr::filter() 的底層原理，第 7 章會用更好讀的寫法做同一件事。

▍R 從 1 開始數

如果你有 Python 經驗，請記住這點：R 的第一個元素是 [1] 不是 [0]。字數[0] 不會報錯，但會回傳一個空向量——又是一個安靜的陷阱。

5. NA：缺失值

NA 代表「這格沒有資料」。它有傳染性：任何跟 NA 做的運算，結果都是 NA。

R
有缺 <- c(412, NA, 288)

mean(有缺)                 #> [1] NA          ← 不是錯誤，是提醒你資料有洞
mean(有缺, na.rm = TRUE)   #> [1] 350         ← 明確表示「忽略缺失值」
is.na(有缺)                #> [1] FALSE  TRUE FALSE

R 的設計哲學是：不幫你決定怎麼處理缺失值。na.rm = TRUE 要你自己打，是為了逼你意識到「我正在丟掉一些資料」。做研究時這是好事——你應該在論文裡交代你怎麼處理缺失值。

6. 資料框：向量並排起來

把幾個等長的向量並排，就是一張表：

R
d0 <- data.frame(委員 = c("甲", "乙"), 字數 = c(412, 631))
d0
#>   委員 字數
#> 1   甲  412
#> 2   乙  631

str(d0)
#> 'data.frame': 2 obs. of  2 variables:
#>  $ 委員: chr  "甲" "乙"
#>  $ 字數: num  412 631

每一欄是一個向量，而且各欄可以是不同型別——這就是資料框跟矩陣的差別。你這學期處理的每一份資料，包括那 162 筆質詢，本質上都是這樣一疊並排的向量。

用 $ 取出某一欄，得到的就是一個向量，前面學的所有東西都能用：

R
d0$字數           #> [1] 412 631
mean(d0$字數)     #> [1] 521.5

  2. 建立 提到能源 <- c(TRUE, FALSE, TRUE, TRUE, FALSE)，用 sum() 算有幾筆是 TRUE，再用 mean() 算比例。想一下為什麼 mean() 會給你比例。

管線與 dplyr 五動詞

本章目標：用五個動詞加一根管線，把「誰的質詢最長」這種問題變成一段可以從左讀到右的程式碼。

本頁章節
管線是什麼五個動詞filter 與 selectmutate 與 arrangegroup_by 與 summarise串成完整管線動手練習本章小結

1. 管線是什麼

假設要做三件事：算字數、只留第 1 會期、由長到短排序。不用管線的寫法是層層包住：

R · 難讀的寫法
arrange(filter(mutate(d, 字數 = nchar(說明)), 會期 == 1), desc(字數))

這行要從裡往外讀，而且括號數量會隨步驟增加而失控。管線 |> 把它攤平成從左到右的一串動作：

R · 管線寫法
d |>
  mutate(字數 = nchar(說明)) |>
  filter(會期 == 1) |>
  arrange(desc(字數))

x |> f() 的意思就是 f(x)——把左邊的東西送進右邊函數的第一個位置。快捷鍵 Cmd/Ctrl+Shift+M（需先完成第 2 章的必改設定第 2 項）。

讀這段程式碼時，在心裡把 |> 唸成「然後」：拿 d，然後算字數，然後只留第 1 會期，然後由長到短排。

▍|> 與 %>%

你會在網路教學與論文附錄裡看到 %>%，那是 magrittr 套件的管線，比 |> 早出現很多年。在本課的用途上兩者等價。差別是 |> 是 R 4.1 起內建的，不需要載入任何套件。本教材一律用 |>；看到 %>% 時直接當成同一個東西讀即可。

2. 五個動詞

動詞做什麼改變了什麼
filter()挑列列數變少，欄數不變
select()挑欄欄數變少，列數不變
mutate()新增或修改欄欄數變多，列數不變
arrange()排序列的順序改變，內容不變
summarise()聚合成摘要多列變一列（搭配 group_by() 則變成每組一列）

五個動詞有一個共同規則：第一個參數都是資料，回傳的也都是資料。正因如此它們才能用管線無限串接。

3. filter 與 select

R
d |>
  filter(會期 == 1) |>
  select(委員, 事由)

#>   委員   事由

注意 == 是兩個等號。一個等號是賦值，兩個才是「等於嗎」。這是所有程式語言新手都會犯一次的錯，犯過就記住了。

條件可以組合，逗號代表「而且」：

R
d |> filter(會期 == 1, 委員 == "羅智強")     # 而且
d |> filter(會期 == 1 | 會期 == 3)           # 或（直立線）
d |> filter(會期 %in% c(1, 3))               # 同上，更好讀
d |> filter(!委員 == "羅智強")               # 驚嘆號＝否定

5. group_by 與 summarise

這組是 dplyr 最有威力的地方：先分組，再對每組算摘要。

R
d |>

  group_by(會期) |>
  summarise(件數 = n(),

6. 串成完整管線

把學到的全部串起來，回答一個實質問題：質詢量達 5 篇以上的委員裡，誰平均寫得最長？

R
d |>
  mutate(字數 = nchar(說明)) |>
  group_by(委員) |>
  summarise(件數 = n(), 平均字數 = round(mean(字數))) |>
  filter(件數 >= 5) |>
  arrange(desc(平均字數)) |>
  head(5)
#> # A tibble: 5 × 3
#>   委員    件數 平均字數
#>   <chr>  <int>    <dbl>
#> 1 羅智強    67      747
#> 2 陳菁徽    14      732
#> 3 吳宗憲    10      653
#> 4 鍾佳濱     6      549
#> 5 顏寬恒     8      539

六行程式碼，從原始資料到一個可以寫進報告的結果。注意 filter() 出現在 summarise() 之後——這時它篩的是「每位委員一列」的摘要表，不是原始的 162 列。同一個動詞放在管線的不同位置，意義完全不同，這是讀懂別人程式碼的關鍵。

管線出錯時，從最上面開始，一次只執行到某一個 |> 為止（選取那幾行按 Cmd/Ctrl+Enter），看每一步的中間結果。哪一步的列數或欄數不對，問題就在那裡。

字串處理 stringr

本章目標：學會六個 stringr 函數與最小必要的正規表達式，然後動手解決這份語料真正的髒污——漢字之間的空白。

本頁章節
六個函數正規表達式最小集問題現場動手清理關鍵詞檢索抽取動手練習本章小結

1. 六個函數就夠用

stringr 的函數全部以 str_ 開頭，第一個參數都是字串向量，而且全部向量化——你對一個字串怎麼做，對 162 筆就怎麼做。

R
library(stringr)
s <- "本院羅委員智強，就文化部發放文化成年禮金政策"

str_length(s)                    #> [1] 22          幾個字元
str_sub(s, 1, 6)                 #> [1] "本院羅委員智"   取第 1 到 6 個字
str_detect(s, "文化")            #> [1] TRUE        有沒有出現
str_count(s, "文化")             #> [1] 2           出現幾次
str_replace_all(s, "文化", "教育")
#> [1] "本院羅委員智強，就教育部發放教育成年禮金政策"
str_split("能源、教育、交通", "、")
#> [[1]]
#> [1] "能源" "教育" "交通"
▍str_replace() 與 str_replace_all()

沒有 _all 的版本只換第一個。清理資料時幾乎永遠要用 _all，這個差別造成的錯誤很難發現，因為程式不會報錯，只是沒換乾淨。

2. 正規表達式最小集

正規表達式（regex）是描述「什麼樣的字串」的語法。完整學會要花很久，但文本分析日常只需要這幾個：

寫法意思例子
.任意一個字元"能.政策" 可配「能源政策」
\\d一個數字"\\d+" 抓「93,800」裡的數字串
\\s一個空白本章主角
+ / *前面那個出現 1 次以上 / 0 次以上"\\s+" 連續空白
[abc]括號內任一個"[，。；]" 中文標點
^ / $開頭 / 結尾"^本院" 以「本院」開頭
\\p{Han}一個漢字處理中文的關鍵武器
(?<=X) (?=X)前面是 X／後面是 X（但不含 X 本身）見下一節
▍為什麼是兩個反斜線

regex 本身要的是 \d，但 R 的字串裡 \ 是逃脫字元，所以你得打 \\d，R 才會把一個 \ 傳給 regex 引擎。這是 R 初學者在 regex 上卡最久的一件事，記住「regex 裡的反斜線在 R 裡要打兩次」就好。

3. 問題現場

把第 2 筆質詢的中段印出來看：

R
str_sub(d$說明[2], 150, 210)
#> [1] "023 年查扣非法走私之加熱菸即高達 93,800 多條，早就塞爆海關 倉庫。其間，造成海關人員的負擔，不僅要負擔人力與保"

看到「海關 倉庫」中間那個空白了嗎？原始資料來自立法院的 PDF 公報，PDF 為了左右對齊會在字元之間插入空白，轉成文字時就留下來了。第 1 章提過的「被 沒 收」也是同一個來源。

為什麼非清不可：斷詞工具會把空白當成詞的邊界。不清的話，「海關倉庫」會被切成「海關」和「倉庫」兩個詞——這個例子看起來還好，但「被 沒 收」會被切成三個單字，你的詞頻表就會多出一堆莫名其妙的單字詞。這會直接污染第 13 章的文件特徵矩陣。

4. 動手清理

我們要的規則是：當一個空白的前面是漢字、後面也是漢字時，刪掉它。前後都是漢字才刪，是為了保留「93,800 多條」這種數字與中文之間的合理空白。

R
乾淨 <- str_replace_all(d$說明[2], "(?<=\\p{Han})\\s+(?=\\p{Han})", "")

str_sub(乾淨, 150, 210)
#> [1] "023 年查扣非法走私之加熱菸即高達 93,800 多條，早就塞爆海關倉庫。其間，造成海關人員的負擔，不僅要負擔人力與保管"

拆解這個 regex：(?<=\\p{Han}) 是「往回看，前面得是漢字」，\\s+ 是「一個以上的空白」（這才是要被刪掉的部分），(?<=...) 與 (?=...) 這兩個往回看／往前看的條件不會被替換掉，所以漢字本身安然無恙。替換成 "" 就是刪除。

套用到整欄，並確認影響範圍：

R
d <- d |>
  mutate(說明清理 = str_replace_all(說明, "(?<=\\p{Han})\\s+(?=\\p{Han})", ""))

round(mean(str_length(d$說明)))        #> [1] 631   清理前
round(mean(str_length(d$說明清理)))    #> [1] 620   清理後
sum(d$說明 != d$說明清理)              #> [1] 162

最後這個數字是本章最重要的發現：162 筆全部都被改動過，平均每筆刪掉約 11 個假空白。也就是說，如果你沒做這一步就直接斷詞，整份語料沒有一筆是乾淨的。

▍清理過的資料要另存一欄

注意我們是 mutate() 出一個新欄位 說明清理，而不是覆蓋 說明。保留原始欄位讓你隨時能回頭比對、驗證清理有沒有做錯事。這也呼應第 3 章的紀律：原始資料只讀不改。

5. 關鍵詞檢索

str_detect(說明, "能源") 只能抓到字面上出現「能源」兩個字的，抓不到講「電價」「核電」「綠電」「再生能源政策」但沒寫「能源」二字的。這就是課程第 4 週字典法會討論的效度問題，也是為什麼後面要走到詞嵌入與 Transformer。工具的限制，就是方法的動機。

6. 抽取：str_extract

str_extract() 把符合的部分「抓出來」而不是判斷有沒有：

R
str_extract(head(d$事由, 3), "本院(.+?)委員(.+?)，")
#> [1] "本院羅委員智強，" "本院黃委員健豪，" "本院馬委員文君，"

.+? 裡的問號代表「非貪婪」——盡量少抓。沒有問號的 .+ 會一路抓到整句最後一個「，」為止。貪婪與非貪婪是 regex 第二個容易踩的坑，記得先試小樣本再套用全欄。

7. 動手練習

  1. 對 d$說明[1] 做一次清理，用 str_length() 比較清理前後的長度差幾個字。
  2. 找出提到「教育」的質詢有幾筆，分別屬於哪些會期。
  3. 用 str_count(d$說明清理, "，") 算每筆的逗號數，再和字數做比較——想想這個數字能不能當成「句子複雜度」的粗略代理指標，以及它的問題在哪。
  4. 試著寫一個 regex 抓出說明裡所有的數字（提示：\\d+），用 str_extract_all()，觀察它跟 str_extract() 回傳的結構差在哪。
  5. 把清理用的 regex 改成 "\\s+"（不加前後條件）套用一次，比較兩者結果——你會看到「93,800 多條」被黏成什麼樣子。這個對照能讓你真正理解那兩個條件在做什麼。

迴圈與 purrr

本章目標：知道怎麼對 162 筆資料重複做同一件事，並理解為什麼 R 社群偏好 map() 勝過 for。

本頁章節
for 迴圈map 家族用 map 接斷詞為什麼偏好 map什麼時候還是要用 for動手練習本章小結

1. for 迴圈：先看你原本會怎麼寫

R
結果 <- character(0)           # 先準備一個空容器
for (s in head(d$事由, 3)) {
  結果 <- c(結果, str_sub(s, 1, 10))
}
結果
#> [1] "本院羅委員智強，就文" "本院黃委員健豪，鑑於" "本院馬委員文君，鑑於"

這段能跑，邏輯也清楚。但它有三個問題：你得自己準備容器、自己記得容器該是什麼型別、而且 結果 <- c(結果, ...) 這種每圈都重建一次向量的寫法，在資料量大時會明顯變慢。

更麻煩的是，迴圈跑完之後 s 這個變數還留在你的環境裡，而且是最後一筆的值。這種「殘留物」是很多難以察覺的錯誤的來源。

2. map 家族：同一件事，一行

R
library(purrr)

map_chr(head(d$事由, 3), \(s) str_sub(s, 1, 10))
#> [1] "本院羅委員智強，就文" "本院黃委員健豪，鑑於" "本院馬委員文君，鑑於"

讀法是：拿第一個參數裡的每一個元素，餵進後面那個函數，把結果收集起來。\(s) 是 R 4.1 起的簡寫，等同 function(s)——你可以把它唸成「給我一個東西，我叫它 s」。

函數名稱的後綴決定回傳什麼型別，這是 purrr 最重要的設計：

函數回傳什麼時候用
map_chr()文字向量每筆產生一段文字，例如斷詞結果
map_int()整數向量每筆產生一個計數，例如詞數
map_dbl()數值向量每筆產生一個小數，例如平均值
map_lgl()邏輯向量每筆產生一個判斷
map()list（清單）每筆產生的東西長度不一或結構複雜
R
map_int(head(d$說明清理, 5), str_length)
#> [1] 803 469 532 488 753

map_dbl(list(c(1, 2, 3), c(10, 20)), mean)
#> [1]  2 15

3. 用 map 接斷詞（本章的實際用途）

中文斷詞的 segment() 一次只能處理一段文字，回傳的是一串詞。要把 162 筆全部斷完，正是 map 的主場：

R
library(jiebaR)
w <- worker()      # 建立斷詞器，只要做一次

詞 <- map_chr(head(d$說明清理, 3), \(s) paste(segment(s, w), collapse = " "))

str_sub(詞, 1, 60)
#> [1] "由 藝 FUN 券 轉型 而來 的 文化 成年 禮金 今年 起 擴大 發放 文化部 每年 列 20 億 預算 發給 16"
#> [2] "一 日前 媒體 報導 日本 觀光客 來 臺 旅遊 入境 時 隨身攜帶 之 加熱 菸 產品 通通 被 海關 沒收 讓 他們"
#> [3] "一 據 國家 發展 委員會 推估 於 2028 年 台灣 生育率 將降 至 新低 出生 人口 推估 僅剩 14 萬人 基"

請注意第二筆裡的「被 海關 沒收」——「沒收」被正確地當成一個詞。這就是第 8 章清理的成果：如果沒有先刪掉假空白，jieba 會看到「被 沒 收」，切成三個單字。一個上游的小清理，決定了下游整個詞頻表的品質。

數每筆有幾個詞：

R
map_int(head(d$說明清理, 5), \(s) length(segment(s, w)))
#> [1] 388 228 240 222 318

對照第 6 章的字元數（803、469、532、488、753），可以看出這份語料大約每 2.2 個字元構成一個詞。這個比例之後估算語料規模時會用到。

4. 為什麼偏好 map

不是因為時髦，是因為三個實際好處。

第一，型別有保證。map_chr() 承諾回傳文字向量，如果某一筆意外產生了數字，它會當場報錯，而不是安靜地把整個向量轉型。for 迴圈沒有這個保護，錯誤會一路傳到最後才爆炸。

第二，能直接接進管線。map 是「資料進、資料出」，可以和第 7 章的五動詞串在一起，整段分析維持同一種讀法。

第三，不留殘留物。迴圈變數不會留在環境裡污染後續程式碼。

▍先確定它對，再套用全部

教材裡所有 map 範例都用 head(..., 3) 或 head(..., 5)，這是刻意的習慣：先在三五筆上確認結果正確，再拿掉 head 跑完整份資料。斷詞或呼叫 API 這類耗時的操作，這個習慣能省下大量時間。

5. 什麼時候還是要用 for

map 不是萬靈丹。當每一圈都依賴上一圈的結果時（例如累積計算、逐步逼近的模型），for 反而清楚。當你要做的事情沒有回傳值、只是產生副作用（例如把 100 張圖存到硬碟），purrr 有個專門的 walk()。

不要為了避免 for 而把程式碼寫得更難懂。能讀懂的 for 迴圈，永遠好過一個你自己都看不懂的 map。

6. 動手練習

  1. 用 map_int() 算出前 10 筆質詢各有幾個「，」（提示：搭配 str_count()）。
  2. 把第 3 節的斷詞從 head(..., 3) 改成全部 162 筆，用 system.time() 包起來看跑多久。
  3. 用 mutate() 把詞數加成 d 的新欄位：mutate(詞數 = map_int(說明清理, \(s) length(segment(s, w))))，然後接第 7 章的 group_by() 算各會期平均詞數。
  4. 故意用錯後綴：把第 2 節的 map_chr() 改成 map_int() 執行，讀一下錯誤訊息。這就是「型別有保證」的實際樣子。
  5. 用 for 迴圈重寫練習 1，比較兩種寫法的行數與可讀性，自己判斷哪個好。

7. 本章小結

  • map_*(資料, 函數)：對每個元素做同一件事，收集結果。
  • 後綴決定回傳型別：_chr 文字、_int 整數、_dbl 數值、_lgl 邏輯，無後綴回傳 list。
  • \(x) 是 function(x) 的簡寫（R 4.1 起）。
  • map 的三個好處：型別有保證、可接管線、不留殘留變數。
  • 先用 head() 試三五筆，確認無誤再跑全部。
  • 累積型運算或純副作用時，for 與 walk() 仍有其位置。

讀懂錯誤訊息

本章目標：把「一片紅字」變成可以逐句讀懂的資訊，認得六種最常見的錯誤，並學會判斷問題出在你還是別人。

本頁章節
三種紅字錯誤訊息的解剖六種常見錯誤判斷是誰壞了怎麼問問題AI 協助與課程規定動手練習本章小結

1. 三種紅字，嚴重程度不同

R 印出來的紅字有三種，新手常一律當成「壞了」，其實只有第一種真的停下來。

類型意思你該做什麼
Error停了，那行沒有執行完必須處理。後面的程式碼是在錯誤的狀態下跑的，不要忽略。
Warning跑完了，但結果可能不是你要的一定要看懂。Warning 常代表資料被安靜地改掉了。
Message只是在跟你說話通常可以忽略。library() 的載入訊息、readr 的欄位型別報告都屬於這類。
R Console
log("abc")
#> Error in log("abc") : non-numeric argument to mathematical function

as.numeric("abc")
#> [1] NA
#> Warning message:
#> NAs introduced by coercion

第二個例子正是 Warning 的危險之處：它回傳了一個 NA，而且程式繼續往下跑。如果這是在清理資料的中途，你的整欄數字可能已經悄悄變成一堆 NA，卻要到很後面算平均時才發現不對。

2. 錯誤訊息的解剖

現代 R（tidyverse 套件尤其如此）的錯誤訊息是有結構的。以打錯欄位名為例：

R Console
d |> filter(會其 == 1)

#> Error in `filter()`:                 ← ① 哪個函數出的錯
#> ℹ In argument: `會其 == 1`.          ← ② 哪個參數有問題
#> Caused by error:                     ← ③ 真正的原因在下一行
#> ! object '會其' not found             ← ④ 找不到叫「會其」的東西

讀的順序是由下往上：先看最後一行的真正原因（④），再往上找它發生在哪裡（②①）。這裡的原因是「會其」不存在——因為正確的欄位名是「會期」。

▍三個讀訊息的訣竅

第一，找引號裡的名字，那通常就是打錯的東西。第二，看到 not found 先想「打錯字」或「忘了載入套件」。第三，訊息很長時，最有用的資訊在最後一行，中間那一大串 Backtrace 是給套件開發者看的，你多半不需要。

3. 六種常見錯誤

object '質詢資料' not found變數不存在：打錯字，或那一行你根本沒執行看 Environment 面板有沒有這個物件；往上把該跑的行跑一次

4. 判斷是誰壞了

這是本章最重要、也最難的一節。當程式不動時，可能性有四種，解法完全不同：

程式不動了
│
├─ 訊息說某個名字找不到 ─────────► 你打錯字，或沒載入套件／沒執行某行
│
├─ 訊息說型別或維度不對 ──────► 你的資料不是你以為的樣子 → class(), dim(), glimpse()
│
├─ 安裝時 compilation failed ─────► 套件本身的問題（第 4 章的 jiebaR 案例）
│
└─ 程式碼沒改過，昨天可以今天不行 ► 外部世界變了：套件更新、API 改版、網路或權限
四種可能性的分流。前兩種是你的問題，後兩種不是——分清楚才不會浪費時間往錯的方向修。

第四種最容易讓人懷疑人生，而本課的語料就有一個現成案例。授課教師維護的 legisTaiwan 套件，原本是抓立法院資料最方便的方式，但在 2026-09-17 實測時：

R Console
library(legisTaiwan)
get_ly_interpellations(term = 11, limit = 20)
#> Fetching interpellation data...
#> Error: API request failed with status code: 404

你的程式碼沒有錯，套件也安裝成功了。404 的意思是「伺服器上沒有這個位址」。這時候要做的不是反覆重裝套件，而是繞過套件、直接問 API 本人：

terminal
curl -s -o /dev/null -w "%{http_code}\n" "https://ly.govapi.tw/v2/interpellations?limit=2"
# 200

API 回 200，表示資料來源是好的，壞的是套件裡寫死的那個網址——套件呼叫的端點與現行 API 版本已經不一致。判斷出這一點之後，解法就清楚了：直接用 httr2 呼叫 API（本課語料的取材腳本 fetch-corpus.R 就是這樣寫的），並到套件的 GitHub 開一個 issue 告知作者。

▍這個判斷力才是重點

「先確認底層服務活著，再回頭懷疑中間那層」是通用的除錯思路，不限於 R。這門課後面會大量依賴外部套件與 API——Hugging Face 的模型、各種資料來源——每一個都可能在學期中途改版。能自己做這個判斷，你就不會卡住。

從 CSV 到 corpus

本章目標：認識 quanteda 的三層結構，把那張 162 列的表格變成一個帶有中繼資料的語料庫物件。

本頁章節
三層結構建立 corpusdocvarssummary為什麼不直接用表格動手練習本章小結

1. quanteda 的三層結構

這門課第 4 週之後的每一次操作，幾乎都是在這三層之間移動。先把這張圖記起來，後面就不會迷路。

data.frame / tibble   一列一篇，還是普通表格
        │  corpus()
        ▼
corpus                  語料庫：文本 ＋ 每篇的中繼資料（docvars）
        │  tokens()
        ▼
tokens                  斷詞後：每篇變成一串詞，順序還在
        │  dfm()
        ▼
dfm                     文件特徵矩陣：列＝文件、欄＝詞、值＝次數
                          順序沒了 —— 這就是「詞袋」
三層各有各的用途，而且是單向的：一旦進了 dfm，詞的順序就不可能還原。什麼時候該停在 tokens、什麼時候可以進 dfm，是方法設計的決定，不是技術問題。

2. 建立 corpus

接續第二篇的資料（記得先做第 8 章的空白清理）：

R
library(quanteda)
library(quanteda.textstats)

co <- corpus(d,
             text_field = "說明清理",     # 哪一欄是正文
             docid_field = "質詢編號")    # 哪一欄當文件編號

ndoc(co)
#> [1] 162

text_field 指定哪一欄是要分析的文本，其餘所有欄位會自動變成 docvars（文件層級變數）。docid_field 指定文件編號，之後在結果裡看到 11-1-1-1 就知道是哪一筆，比 text1、text2 好追。

3. docvars：語料庫的中繼資料

R
names(docvars(co))
#> [1] "屆" "會期" "會次" "委員" "刊登日期" "事由" "說明"

docvars 是 quanteda 最重要的設計。它讓「文本」與「這篇文本是誰在什麼時候說的」綁在一起，之後你要做的每一種分組比較——不同會期的用詞差異、不同委員的風格、時間趨勢——都靠它。

▍先想清楚要哪些 docvars

做研究時，corpus 建立的那一刻就決定了你之後能問什麼問題。如果建 corpus 時沒帶入政黨、選區、委員會這些欄位，後面想比較就得整個重來。收集資料時多留幾個中繼欄位，成本很低，回頭補很貴。

4. summary 看全貌

R
summary(co, n = 4)[, 1:4]
#>         Text Types Tokens Sentences
#> 1   11-1-1-1   277    490        15
#> 2 11-1-20-63   184    279         7
#> 3 11-1-20-64   194    296         9
#> 4 11-1-20-65   165    278         6

三個欄位要分清楚：Tokens 是總詞數（這篇講了幾個詞），Types 是不重複詞數（用了幾種詞），Sentences 是句數。Types ÷ Tokens 叫型符比（type-token ratio），常被拿來當詞彙豐富度的粗略指標——第一篇 277/490 ≈ 0.57。

▍加上 [, 1:4] 是有原因的

summary(co) 會把所有 docvars 一起印出來，而我們的 docvars 裡有「事由」和「說明」兩個長文本欄位——直接執行會在 Console 噴出數千字，完全看不了。這是實測踩到的坑，取欄位是必要的。

5. 為什麼不直接用表格就好

你可能會想：資料本來就在 tibble 裡，用第 7 章的 dplyr 不就夠了嗎？

對於「算字數、依委員分組」這類操作，確實夠。但 corpus 之後的兩層才是重點——tokens 與 dfm 是專門為文本設計的資料結構，有 tibble 給不了的東西：dfm 是稀疏矩陣，162 篇 × 六千多個詞如果存成一般表格會浪費大量記憶體；而課程後面要用的主題模型（stm）、尺度分析（Wordfish）、分類器，它們的輸入介面就是 dfm。

簡單說：dplyr 負責整理與篩選，quanteda 負責文本本身。兩者在同一段管線裡並用是常態。

▶ 影片示範 · quanteda 入門 待補
quanteda 的影片教學極少，搜尋結果品質都不足以放進教材（查證日 2026-09-18）。官方文件反而是更好的資源：tutorials.quanteda.io 有完整的互動教學，從 corpus 一路到主題模型，也是課程後續週次會用到的參考。

6. 動手練習

  1. 建立 corpus，確認 ndoc() 是 162、names(docvars(co)) 有七個欄位。
  2. 執行 summary(co, n = 10)[, 1:4]，找出前十篇裡 Types/Tokens 比例最高的是哪一篇。
  3. 用 corpus_subset(co, 會期 == 3) 取出第 3 會期的子語料庫，看看 ndoc() 剩幾篇（對照第 7 章 count() 的結果，應該一致）。
  4. 故意不加 [, 1:4] 執行一次 summary(co, n = 2)，感受一下為什麼要取欄位。準備好按 Ctrl+L 清畫面。
  5. 把 docid_field 拿掉重建一次 corpus，觀察文件編號變成什麼。

7. 本章小結

  • 三層結構：corpus（文本＋中繼資料）→ tokens（斷詞、保留順序）→ dfm（詞袋、順序消失）。
  • corpus(d, text_field = , docid_field = )；其餘欄位自動成為 docvars。
  • docvars 決定你之後能做哪些分組比較，建 corpus 前先想清楚。
  • summary(co) 的 Types／Tokens／Sentences 三個欄位意義不同；有長文本 docvars 時務必取欄位。
  • dplyr 管整理、quanteda 管文本，兩者並用。

斷詞：英文與中文

本章目標：學會 tokens() 的常用選項，並用實測結果搞清楚中文斷詞到底該不該用 jieba。

本頁章節
英文斷詞清理選項中文的真相ICU 與 jieba 實測對照自訂詞典全語料斷詞動手練習本章小結

1. 英文斷詞：空白幫你做完了

R
tokens("Text as data: a method for social science!")
#> Tokens consisting of 1 document.
#> text1 :
#>  [1] "Text"    "as"      "data"    ":"       "a"       "method"  "for"
#>  [8] "social"  "science" "!"

英文用空白分隔，斷詞幾乎是免費的。注意標點被切成獨立的 token——這是預設行為，通常要清掉。

2. 清理選項

R
tokens("Text as data: a method for social science!", remove_punct = TRUE)
#> text1 :
#> [1] "Text"    "as"      "data"    "a"       "method"  "for"     "social"
#> [8] "science"

常用的幾個：remove_punct（標點）、remove_numbers（數字）、remove_symbols（符號）、remove_url（網址）。

▍每一個 remove 都是研究決定

移除數字聽起來無害，但如果你研究的是預算案，「20 億」「93,800 條」正是重點。沒有一組通用的正確設定——每個選項都該問一次「這對我的研究問題會不會拿掉重要資訊」。這類決定在論文的方法章節要交代清楚，也是第 4 週課程把「斷詞、DFM、字典法」放在同一週講的原因——前處理的每個決定都會一路影響到情緒分數。

3. 中文的真相

中文字與字之間沒有空白，所以「中文一定要先用 jieba 斷詞」是常見的說法。但這句話不完全正確，實際測一下就知道：

R
tokens("能源政策與經濟發展的平衡")
#> text1 :
#> [1] "能源" "政策" "與"   "經濟" "發展" "的"   "平衡"

quanteda 斷得相當漂亮——因為它底層用的是 ICU 的詞界偵測，本來就內建中日韓的詞典式斷詞能力，不是單純照空白切。

那 jieba 還有沒有價值？有，但差別在細節，不在有無。

4. ICU 與 jieba 實測對照

拿四個句子實際比對（2026-09-18 實測，quanteda 4.5.0 與 jiebaR 0.11）：

原句quanteda 內建（ICU）jiebaR

加熱菸產品通通被海關沒收加熱/菸/產品/通通/被/海關/沒收加熱/菸/產品/通通/被/海關/沒收　相同

結論很清楚：四句裡兩句完全相同，差異出在複合詞（環境保護）與人名（智強）。jieba 在這兩類上略勝，因為它帶著一份中文詞典。

但真正決定性的優勢不是預設表現，而是下一節——jieba 可以加詞。

▍所以這門課為什麼教 jieba

不是因為 quanteda 不能斷中文，而是因為政治文本充滿專有名詞：政策名、機關名、委員姓名。這些詞不在任何通用詞典裡，必須自己補。能補詞的工具才有用——這是選擇 jieba 的真正理由，不是「中文非它不可」。

5. 自訂詞典：本章最有用的一招

「文化成年禮金」是一個政策名稱，應該是一個詞，但預設會被拆開：

R
library(jiebaR)
w <- worker()

segment("文化成年禮金政策", w)
#> [1] "文化" "成年" "禮金" "政策"        ← 政策名被拆成三塊

new_user_word(w, c("文化成年禮金", "加熱菸", "國健署"))
#> [1] TRUE

segment("文化成年禮金政策", w)
#> [1] "文化成年禮金" "政策"            ← 正確了

segment("加熱菸產品通通被海關沒收", w)
#> [1] "加熱菸" "產品" "通通" "被" "海關" "沒收"

注意第二個例子：加了詞之後，「加熱/菸」合併成「加熱菸」——這是菸害防制法裡的法定名詞，拆開就失去意義了。

▍自訂詞典是可重現性的一部分

你加了哪些詞，會直接改變詞頻表與後續所有模型的結果。把自訂詞清單寫進腳本、納入版本控制、在論文附錄交代，不要臨時在 Console 加一加就跑分析。這正是課綱要求「標註規程」列入附錄的理由。

詞多的時候，可以把詞寫成一個純文字檔（一行一詞），建立 worker 時直接載入：worker(user = "my_dict.txt")。

6. 全語料斷詞

把第 9 章的 map_chr() 接上來，跑完 162 筆：

R
seg <- map_chr(d$說明清理, \(s) paste(segment(s, w), collapse = " "))

co2 <- corpus(seg, docvars = d |> select(委員, 會期, 會次))
tk  <- tokens(co2, remove_punct = TRUE, remove_numbers = TRUE)

head(ntoken(tk), 5)
#> [1] 409 238 245 232 313

sum(ntoken(tk))                          # 總詞數
#> [1] 49975
length(unique(unlist(as.list(tk))))      # 不重複詞型
#> [1] 6471

做法是：jieba 斷好之後用空白把詞接回一個字串，再交給 quanteda——這樣 quanteda 只要照空白切就好，等於把中文變成「英文那樣的形式」。這是 R 社群處理中文最常見的做法。

五萬詞、六千多個詞型。這個規模在文本分析裡算小，但已經足夠讓你在自己的筆電上跑完整個流程而不用等待，很適合學習。

7. 動手練習

  1. 拿三個你自己想到的政治或政策名詞，先看預設怎麼斷，再用 new_user_word() 加入後重斷，比較差異。
  2. 把 remove_numbers = TRUE 拿掉重跑一次，比較 sum(ntoken(tk)) 差多少。想一想：如果研究題目是預算或統計數據，這個選項該怎麼設？
  3. 用 ICU（直接 tokens(d$說明清理[1])）與 jieba 各斷第一篇，比較 ntoken() 差幾個詞。
  4. 建立一個 my_dict.txt，放五個委員姓名，用 worker(user = "my_dict.txt") 載入測試。
  5. 用 kwic(tk, "政策", window = 5) 看「政策」這個詞出現時前後五個詞是什麼——這叫關鍵詞脈絡（keyword in context），是檢查斷詞品質最快的方法。

  • tokens() 的 remove 選項每一個都是研究決定，要在方法章節交代。
  • quanteda 內建的 ICU 斷詞已經能處理中文，實測四句有兩句與 jieba 完全相同。
  • 差異在複合詞與人名；jieba 的真正優勢是可以加詞。
  • new_user_word() 加入政策名與專有名詞，清單要納入版本控制與論文附錄。

dfm 與停用詞

本章目標：建立文件特徵矩陣，理解它為什麼那麼空，並親手處理中文停用詞這個沒有標準答案的問題。

本頁章節
建立 dfm稀疏度沒去停用詞的樣子中文停用詞的麻煩去除與修剪tf-idf動手練習本章小結

1. 建立 dfm

R
dm0 <- dfm(tk)
dim(dm0)
#> [1]  162 6469

162 列（文件）× 6,469 欄（詞型），每一格是「這個詞在這篇出現幾次」。這就是詞袋模型（bag of words）——第 4 週課程的核心概念。

「袋」這個比喻很傳神：詞被倒進袋子裡，誰先誰後完全消失。「政府不應該補助」和「不應該政府補助」在 dfm 裡一模一樣。這個簡化是所有後續方法（字典法、主題模型、尺度分析）的共同前提，也是它們共同的限制。

2. 稀疏度：為什麼矩陣幾乎是空的

R
sparsity(dm0)
#> [1] 0.971

97.1% 的格子是零。想一下就知道很合理：一篇六百字的質詢頂多用到三四百個詞，而詞彙表有六千多個詞，剩下的當然都是零。

這是文本資料的普遍性質，也是為什麼 dfm 用稀疏矩陣儲存——只記非零的格子。如果存成一般矩陣，162 × 6,469 個數字裡有九成七是無意義的零。真實研究動輒數萬篇文件、數十萬詞型，不用稀疏矩陣根本存不下。

3. 沒去停用詞的樣子

R
topfeatures(dm0, 12)
#>   的   之   與   年   為   及   在   以   有   應 政府 政策
#> 1393  556  443  420  386  369  285  271  241  231  217  202

前十名幾乎全是虛詞。「的」出現 1,393 次，是第十一名「政府」的六倍以上。這個表格什麼也沒告訴你——它只是重新確認了中文的語法。

這就是停用詞（stop words）要解決的問題：把高頻但沒有區辨力的詞拿掉。

4. 中文停用詞的麻煩

英文有公認的停用詞表，stopwords("en") 直接用就好。中文沒有這麼幸運，而且對台灣的研究者還多一層問題。

stopwords 套件確實有中文清單，但實測後會發現：

R
library(stopwords)
sw <- stopwords("zh", source = "misc")
length(sw)
#> [1] 647
head(sw, 12)
#> [1] "按" "按照" "俺" "们" "阿" "别" "别人" "别处" "是" "别的" "别管" "说"

這是簡體中文的清單（们、别、说）。套用到繁體語料上會發生什麼？實測結果比想像中微妙：

R
hit <- intersect(featnames(dm0), sw)
length(hit)
#> [1] 222                                 ← 還是命中了 222 個詞

dim(dfm_remove(dm0, sw))
#> [1]  162 6247                           ← 從 6469 降到 6247

# 但前八高頻詞裡，哪些沒被移除？
#> 前八高頻詞：的/之/與/年/為/及/在/以
#> 被移除的：  的/之/年/及/在/以
#> 漏掉的：    與、為

簡體清單之所以還能命中 222 個詞，是因為很多虛詞在兩種字體下寫法相同（的、之、在、以）。但它漏掉的「與」「為」——簡體寫作「与」「为」——剛好都是高頻詞。

所以結論是：可以拿簡體清單當起點，但不能直接用。實務做法是先看 topfeatures()，把明顯的虛詞手動補上，並且把這份清單當成研究材料的一部分寫進附錄。

▍停用詞是研究決定，不是技術細節

本教材的清單裡有「政府」嗎？沒有。但如果你的研究問題是「委員多常訴諸政府責任」，「政府」就是核心詞；如果你研究的是政策議題分布，「政府」可能是雜訊。同一個詞在不同研究裡地位完全不同，沒有一份清單能通用。刪掉的每個詞都要說得出理由。

5. 去除與修剪

R
stop_zh <- c("的","是","與","及","在","為","對","於","並","以","有","也","等","將","其","之",
             "而","了","要","從","或","我國","本院","委員","質詢","行政院","特向","提出",
             "鑑於","就","應","不","及其","請","可","該","此","已","但","一","二","三","中",
             "上","後","更","至","者","因","年","月","日","無","由","被","所","都","如","個")

dm <- dfm_remove(dm0, stop_zh, valuetype = "fixed") |>
      dfm_trim(min_termfreq = 5)

dim(dm)
#> [1]  162 1964
sparsity(dm)
#> [1] 0.9376

兩個動作做了不同的事。dfm_remove() 依清單刪除；dfm_trim(min_termfreq = 5) 刪掉全語料出現不到 5 次的詞。後者砍掉的量其實更大——6,469 個詞型裡，絕大多數只出現一兩次（這是語言的齊夫定律）。

詞型從 6,469 降到 1,964，稀疏度從 0.971 降到 0.938，矩陣變得比較密實，後續模型也跑得動。

成果：

R
topfeatures(dm, 15)
#> 政府 政策   人 相關 問題 學生   能 針對 根據   化 社會 民眾 詐騙 導致   部
#>  217  202  140  137  135  115  111  110  105  104  104  102   99   95   93

比剛才有意義了，但還是有「人」「相關」「能」「化」這種近乎虛詞的東西混在裡面。這就是實際做研究的樣子——清理是反覆的，不是一次到位。

6. tf-idf：另一種看法

與其一直手動刪詞，有個更聰明的角度：與其問「哪個詞出現最多次」，不如問「哪個詞在少數幾篇裡特別集中」。那才是有區辨力的詞。

R
topfeatures(dfm_tfidf(dm), 8)
#>      詐騙      學生      政策      護理      住宅      疫苗      人員        學
#> 111.90304 102.03901  81.47368  76.40735  74.60203  73.94293  72.36807  70.54695

對照一下原始詞頻的前幾名（政府、政策、人、相關、問題），tf-idf 給出的是詐騙、學生、護理、住宅、疫苗——這些一看就知道是實際的政策議題。「政府」掉出榜首，因為它到處都有，反而不能區分任何一篇。

tf-idf 的邏輯是：詞頻（term frequency）乘上逆文件頻率（inverse document frequency）。一個詞在某篇出現很多次、但在其他篇很少出現，分數就高。

▍這個對照本身就是一個小發現

兩張表的差異，正好示範了「同一份資料、不同權重方式，看到的東西完全不同」。這是課程第 5 週「描述與比較文本」的核心議題。你在報告裡呈現哪一張表，就等於選擇了一種對「重要」的定義——而那個選擇要有理由。

7. 動手練習

  1. 調整 dfm_trim() 的門檻：試 min_termfreq = 2、10、20，記錄每次的詞型數與稀疏度，畫成一張小表。
  2. 把「政府」「政策」也加進停用詞清單重跑，看 topfeatures() 變成什麼。你覺得這樣做合理嗎？在什麼研究問題下合理？
  3. 用 dfm_subset(dm, 會期 == 1) 取出第 1 會期，比較它與全體的 topfeatures()。
  4. 試 dfm_weight(dm, scheme = "prop")（轉成比例），看 topfeatures() 的數字變成什麼意思。
  5. 找出只出現一次的詞有幾個：sum(colSums(dm0) == 1)，算算佔全部詞型的比例。這個數字會讓你對語言的長尾有感。

8. 本章小結

  • dfm＝文件特徵矩陣，列是文件、欄是詞、值是次數；詞序消失，這就是詞袋模型。
  • 本課語料原始 dfm 為 162 × 6,469，稀疏度 0.971（97.1% 是零）。
  • 不去停用詞時，前十名幾乎全是虛詞，「的」出現 1,393 次。
  • stopwords("zh") 是簡體清單，命中 222 個詞但漏掉「與」「為」等高頻繁體虛詞——可當起點，不能直接用。
  • dfm_remove() 依清單刪、dfm_trim() 依頻率刪；處理後為 162 × 1,964。
  • tf-idf 換一個角度看重要性：詐騙、學生、護理、住宅、疫苗浮現，「政府」退場。
  • 停用詞清單與修剪門檻都是研究決定，要寫進方法與附錄。

描述統計與第一張圖

本章目標：把 dfm 變成可以放進報告的表與圖，並做出這份語料的第一個實質發現。

本頁章節
textstat_frequency畫第一張圖中文字型問題分組比較存檔與可重現接到課程哪裡動手練習本章小結

1. textstat_frequency：從矩陣到表格

topfeatures() 回傳的是一個具名向量，不方便畫圖。textstat_frequency() 直接給你一張整齊的表：

R
library(quanteda.textstats)
f <- textstat_frequency(dm, n = 10)
f
#>    feature frequency rank docfreq group
#> 1     政府       217    1      91   all
#> 2     政策       202    2      64   all
#> 3       人       140    3      53   all
#> 4     相關       137    4      83   all
#> 5     問題       135    5      69   all
#> 6     學生       115    6      21   all
#> 7       能       111    7      49   all
#> 8     針對       110    8      71   all
#> 9     根據       105    9      67   all
#> 10      化       104   10      47   all

多出來的 docfreq 欄很有用：它是「有幾篇文件出現過這個詞」。對照 frequency 一起看能看出詞的性質——「政府」出現 217 次、分布在 91 篇（幾乎每兩篇就有一篇），是散布型；「學生」出現 115 次卻只在 21 篇，平均每篇講五次以上，是集中型，代表有少數幾篇專門在談教育議題。

這個 frequency 與 docfreq 的落差，就是上一章 tf-idf 在捕捉的東西。

2. 畫第一張圖

R
library(ggplot2)

p <- ggplot(f, aes(x = reorder(feature, frequency), y = frequency)) +
  geom_col(fill = "#3794ff") +
  coord_flip() +
  labs(title = "立法院第11屆書面質詢：前十高頻詞",
       subtitle = "162 筆，jieba 斷詞後去停用詞",
       x = NULL, y = "出現次數") +
  theme_minimal(base_family = "PingFang TC", base_size = 13)

p

三個值得注意的地方。reorder(feature, frequency) 讓長條依數值排序而不是依字母——沒有這個，圖會亂到無法讀。coord_flip() 把長條轉成橫向，中文詞標籤才不會擠在一起。x = NULL 拿掉沒有資訊量的軸標題。

實際產出：

上圖由本章程式碼實際執行產生（ggsave，7×4.4 吋，130 dpi）。圖面為白底，是 ggplot 預設；要配合深色簡報時需另行設定 theme。

如果你沒寫 base_family，圖上的中文很可能變成空白方塊或豆腐字。ggplot 用的是系統字型，而預設字型不一定含中文。

▍存成 PDF 時另有陷阱

用 ggsave("圖.pdf") 存中文圖時，預設的 PDF 裝置對中文支援不佳，常見缺字。改用 ggsave("圖.png", dpi = 300) 存高解析度 PNG，或加 device = cairo_pdf。期末海報與論文要出 PDF，這件事請提早試，不要留到截稿前。

4. 分組比較：這份語料的第一個發現

單純的詞頻表只能描述，做不了比較。textstat_keyness() 可以回答「A 組相對於 B 組，哪些詞特別突出」：

R
dmg <- dfm_subset(dm, 會期 %in% c(1, 3))
k   <- textstat_keyness(dmg, target = docvars(dmg, "會期") == 3)
head(k, 6)
#>   feature     chi2            p n_target n_reference
#> 1    高齡 41.17236 1.393800e-10       30           1
#> 2      ai 38.57868 5.259019e-10       26           0
#> 3    政策 35.96519 2.008739e-09       74          34
#> 4    生育 35.24817 2.902543e-09       26           1
#> 5    疫苗 33.75175 6.261275e-09       29           3
#> 6      偏 28.18183 1.104363e-07       19           0

讀法：n_target 是在第 3 會期出現幾次、n_reference 是在第 1 會期出現幾次，chi2 是卡方統計量。

「高齡」30 比 1、「AI」26 比 0、「生育」26 比 1——第 3 會期的質詢明顯轉向高齡化、AI 與少子化議題，而第 1 會期幾乎沒有人談。這是一個真實的、從資料裡長出來的觀察。

▍先別急著寫進論文

這個發現有三個致命限制。第一，樣本只有 162 筆，是為教學抓的一小部分，不是母體。第二，第 1 會期 59 筆、第 3 會期 35 筆，數量不對等。第三，前面提過，四成的質詢來自同一位委員——所謂的「會期差異」，可能只是「不同委員在不同時間比較活躍」。

換句話說，你看到的可能是抽樣假象，不是議題變遷。要驗證它，需要完整資料、控制委員層級的變異，並考慮多重比較的問題。這正是課程第 5 週與第 9 週要教的內容——工具讓你很快看到「一個模式」，方法訓練讓你判斷「那是不是真的」。

  1. 把長條圖的 n = 10 改成 20，觀察圖變得好讀還是更亂，想想報告裡該放幾個。
