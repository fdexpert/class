1. 適合誰

寫給修習國立臺灣大學國家發展研究所「文本即數據：社會科學研究的計算方法」（115-1）而完全沒寫過 R 的研究生。你可能用過 SPSS、Stata，或只用過 Excel，甚至完全沒碰過任何程式語言——都沒關係，這份教材從「什麼是 Console」開始講。

如果你有 Python 經驗，第二篇可以跳著讀，但請不要跳過第三章的 Project 工作流，那是 R 社群和 Python 習慣差最多的地方。

2. 為什麼需要這份教材

課綱的「先備知識」寫得很直接：具備 R 使用經驗、能在 Python 環境執行程式碼、會用 RStudio 或 Positron 編輯執行程式與管理套件、會用終端機。第一週的 Lab 就是「在 RStudio 中安裝套件與設定專案」與「建立 GitHub 帳號與儲存庫設定」，第三週就要用 quanteda 做斷詞與建立文件特徵矩陣。

換句話說，這門課把 R 當成已經會的工具，把課堂時間留給方法論。工具不熟的人會在第 3 到第 5 週之間迅速掉隊——不是因為聽不懂主題模型，而是因為卡在讀不進檔案、中文變亂碼、套件裝不起來這些跟課程內容無關的事。這份教材就是要把那些事提前解決掉。

▍這份教材不教什麼

不教統計、不教文本分析方法本身、不教主題模型怎麼解讀——那些是課堂的事。這裡只處理「手」的問題：怎麼把想法變成能跑的程式碼，怎麼把結果變成可以交出去的檔案。

3. 課程地圖

全課約 8 小時，設計成分四次消化，每次約 2 小時。建議不要一天讀完；第二篇之後的內容需要你實際敲過鍵盤才會留下來。

4. 貫穿範例：立法院書面質詢

全課程用同一份真實資料串起來：立法院第 11 屆書面質詢 162 筆，取自立法院開放資料 API，涵蓋第 1 至第 3 會期、28 位委員，每筆有「事由」（一句話摘要）與「說明」（完整質詢內容，平均 617 字）。

選這份資料有三個理由。第一，它是中文，你會真實遇到中文斷詞的問題，而不是拿英文範例練完、上課換中文就傻眼。第二，它是政治文本，正好是課程第 12 週建議的期末題目方向之一（台灣立法行為、立法演說分析）。第三，它不乾淨——原始 PDF 排版在漢字之間塞了空白，會出現「造成許多觀光客抱怨臺灣政策之反覆與延宕」被拆成「造 成 許 多 觀 光 客」的狀況。真實資料就長這樣，我們會在第三篇正面處理它。

▍關於 legisTaiwan 套件

授課教師維護的 legisTaiwan 套件原本是抓這份資料最方便的方式，但 2026-09-17 實測，它的 get_ly_interpellations() 與 get_ly_legislators_by_term() 都回傳 HTTP 404，套件內部呼叫的端點與現行 API 已不一致。底層 API（ly.govapi.tw/v2）本身正常。因此本教材的取材腳本改為直接呼叫 API。這件事本身就是很好的一課：套件會壞，API 會變，你要有能力判斷是誰壞了。第十章會教你怎麼做這個判斷。

R、RStudio、Quarto、GitHub：四件工具的分工

本章目標：搞懂你電腦裡那四個圖示各自負責什麼，以後看到錯誤訊息才知道該去哪裡找。

本頁章節
為什麼要先講這個R 是引擎RStudio 是駕駛艙Quarto 是排版廠GitHub 是交件窗口速查對照表動手練習本章小結

1. 為什麼要先講這個

新手最常見的困惑不是「這行程式碼怎麼寫」，而是「我到底該在哪裡打這行字」。有人在終端機裡打 R 的指令，有人在 R 的 Console 裡打 brew install，然後對著錯誤訊息發呆。這些困惑的根源都一樣：分不清楚這幾個東西的界線。

先把界線畫清楚，後面十八章都會輕鬆很多。

四件工具的分工。實線是你主動觸發的動作，虛線是自動回流的結果。注意：套件掛在 R 底下，不是掛在 RStudio 底下——換 IDE 不用重裝套件，換 R 版本才要。

2. R 是引擎

R 是一個程式語言，也是執行這個語言的程式。它本身沒有漂亮的介面——你可以在終端機打 R 直接啟動它，看到的就是一個 > 提示符號，你打指令、它算給你看，如此而已。

terminal
R --version
# R version 4.6.1 (2026-06-24) -- "Great Square Root"

所有真正的運算——讀檔案、算詞頻、跑主題模型——都是 R 在做。套件（package）也是裝在 R 裡面，不是裝在 RStudio 裡面。這個觀念很重要：你換 IDE，套件不用重裝；你換 R 版本，套件要重裝。

▍你的 R 裝在哪

macOS 上官方版 R 裝在 /Library/Frameworks/R.framework/，指令在 /usr/local/bin/R。套件裝在 /Library/Frameworks/R.framework/Versions/4.6/Resources/library。這條路徑之後排查問題時會用到。

3. RStudio 是駕駛艙

RStudio 是一個 IDE（整合開發環境）。它自己不會算任何東西，它做的事情是：幫你編輯程式碼、把你的程式碼送去給 R 執行、把 R 吐回來的結果排版顯示、順便管理你的檔案、畫圖、查說明文件。

用車來比喻：R 是引擎，RStudio 是方向盤、儀表板和音響。沒有 RStudio 你還是能開（用終端機跑 R），但很難開。沒有 R，RStudio 就是一個打不著火的空殼——事實上 RStudio 啟動時如果找不到 R，會直接跳錯誤。

▍一個立刻能用的判斷法

當你看到錯誤訊息時，先問：這是 R 說的，還是 RStudio 說的？Error in library(quanteda) : there is no package called 'quanteda' 是 R 說的，跟 RStudio 無關，重裝 RStudio 不會有幫助。而「Console 字太小」「面板不見了」則是 RStudio 的事，跟 R 無關。

4. Quarto 是排版廠

Quarto 是一個獨立的命令列工具（不是 R 套件），它把「文字 + 程式碼 + 程式碼跑出來的結果」組合成一份完整文件，輸出成 PDF、HTML 或 Word。

這門課為什麼非用不可：課綱明文要求「實驗報告、論文與海報均須使用 LaTeX／Overleaf 或 Quarto 撰寫，渲染為 PDF」，而且期末論文要附「GitHub 或 CodeOcean 可重現程式碼儲存庫」。Quarto 一次解決兩件事——你的報告和你的程式碼是同一份檔案，改了數據重新 render，表格和圖自己更新，不會出現「論文裡的數字跟程式碼跑出來的不一樣」這種學術災難。

Quarto 底下還串了兩個工具：Pandoc 負責格式轉換，LaTeX（我們裝的是 TinyTeX）負責排出 PDF。你不用直接操作它們，但出錯時錯誤訊息可能來自它們，知道有這層會少走很多冤枉路。

terminal
quarto --version
# 1.10.18

5. GitHub 是交件窗口

Git 是版本控制系統，GitHub 是把 Git 儲存庫放在網路上的服務。這門課用 GitHub Classroom 繳交六份 Lab 作業（成績取最佳三份，佔 20%），期末論文也要附可重現儲存庫。

好消息是課綱明說「不要求 Git 經驗」，你會用 GitHub Desktop，一個圖形介面工具，不用背指令。第 16 章會完整走一遍。

這裡先建立一個觀念：Git 管的是程式碼和文字檔的歷史，不是拿來存資料的雲端硬碟。把幾百 MB 的語料推上 GitHub 是新手最常犯的錯之一，第 16 章會教你用 .gitignore 擋掉。

▍Windows 差異

路徑不同：R 通常在 C:\Program Files\R\R-4.6.1\，套件預設裝在使用者資料夾 C:\Users\你的名字\AppData\Local\R\win-library\4.6。另外 Windows 需要額外安裝 Rtools（cran.r-project.org/bin/windows/Rtools）才能編譯需要 C++ 的套件；macOS 的對應物是 Xcode Command Line Tools。本課有幾個套件（如 jiebaR）會用到編譯，沒裝 Rtools 會失敗。

7. 動手練習

  1. 打開「終端機」（macOS 內建，在 應用程式 → 工具程式；Windows 用 PowerShell），輸入 R --version、quarto --version，確認兩個版本號都印得出來。
  2. 在同一個終端機輸入 R 進入 R 的 Console，打 1 + 1 按 Enter，看到 [1] 2。然後打 q()、再打 n 離開。你剛剛用的就是「沒有 RStudio 的 R」。
  3. 打開 RStudio，在它的 Console 裡一樣打 1 + 1。對照一下：同一個引擎，不同的駕駛艙。
  4. 在 RStudio 的 Console 打 R.home()，看看它指到的路徑是不是上面提過的那個。

8. 本章小結

  • R 是引擎，負責運算，套件裝在 R 裡；RStudio 是駕駛艙，負責讓你舒服地操作 R。
  • Quarto 是獨立工具，把程式碼與文字組成 PDF，課綱的報告格式要求靠它滿足。
  • GitHub 是交件窗口，用 GitHub Desktop 操作即可，不需要背指令。
  • 看到錯誤訊息，先判斷是誰在說話——這是整份教材最省時間的一個習慣。

本頁章節
四大窗格Console 與 Script 的差別執行快捷鍵Environment 面板Help 與 Files六項必改設定動手練習本章小結

1. 四大窗格

第一次打開 RStudio 只會看到三個窗格，左上角的 Source（編輯器）要等你開啟或新建檔案才會出現。下圖是四個窗格的相對位置，實際畫面請對照本節的示範影片。

RStudio 預設的四窗格配置示意（非實際截圖）。藍框的兩格是你最常互動的。窗格位置可在 Settings → Pane Layout 自由調換，因此同學的畫面未必與此圖一致。

左下角窗格還有一個常被忽略的分頁：Terminal。它是真正的系統終端機（macOS 上是 zsh），跟 Console 完全不同——Console 吃 R 語言，Terminal 吃 shell 指令。課綱的先備知識裡「會用終端機」指的就是這個。你不用精通，但要知道 brew install、git status 這類指令屬於 Terminal，不屬於 Console。

2. Console 與 Script 的差別（本章最重要）

這是新手最容易混淆、也最影響學習效率的一件事。

Console 適合試探：想知道 nchar("測試") 回傳什麼，直接在 Console 打，看到答案，丟掉。它是草稿紙。

Script（.R 檔）適合累積：你的分析流程——讀檔、清理、斷詞、建 dfm——要寫在 Script 裡，存檔，明天打開還在，下週改一個參數重跑一次。它是你的作品。

▍新手最常犯的錯

整個分析流程都打在 Console 裡，跑出漂亮結果，然後關掉 RStudio。隔天要重現，全部消失。你的 Lab 作業要繳交可重現的程式碼，Console 裡的東西交不出去。從第一天就養成習慣：凡是會想再跑第二次的，都寫進 Script。

新建 Script 的方式：選單 File → New File → R Script，或直接按 Cmd+Shift+N。

3. 執行快捷鍵

在 Script 裡寫好程式碼後，要把它「送」去 Console 執行。用滑鼠複製貼上是可以，但你一天會做幾百次，請從第一天就用鍵盤。

▍Console 裡的兩個符號

看到 > 表示 R 在等你下新指令，一切正常。看到 + 表示 R 認為你上一行還沒寫完（通常是括號或引號沒關），它在等你補完——這時候按 Esc 取消，回頭檢查括號。這個 + 讓非常多新手以為電腦當機。

4. Environment 面板怎麼讀

右上角 Environment 列出目前記憶體裡所有的物件。你執行 x <- 5 之後，這裡就會出現一列 x 5。讀資料進來之後，會出現類似 d 162 obs. of 8 variables——這是快速確認「我到底讀進了幾筆資料」最方便的地方。

資料框旁邊有個表格圖示，點下去會用試算表的樣子打開資料，適合肉眼檢查。也可以在 Console 打 View(d) 達到同樣效果。

面板上方那把掃帚圖示會清空所有物件（等同 rm(list = ls())）。這是好習慣的一部分：如果你的 Script 只有在「清空環境後從頭跑」才會成功，它才是真的可重現。

?dfm           # 查 quanteda 的 dfm（需先 library(quanteda)）
??"topic model"  # 兩個問號＝全文搜尋，不確定函數名時用

R 的說明文件格式固定：Description（做什麼）、Usage（怎麼呼叫）、Arguments（每個參數的意思）、Value（回傳什麼）、Examples（可以直接複製執行的範例）。新手直接跳到最下面的 Examples 往往最快。

6. 六項必改設定

打開設定：macOS 是選單 RStudio → Settings…（舊版顯示為 Preferences），Windows 是 Tools → Global Options…。以下六項請在上課前改好，每一項都會實際影響你這學期的順暢度。

(1) 關閉工作區自動儲存 — General → Basic

把 Restore .RData into workspace at startup 的勾取消，並把 Save workspace to .RData on exit 設為 Never。

理由：預設行為會在你關閉 RStudio 時把所有變數存下來、下次開啟時還原。聽起來貼心，實際上是可重現性的頭號殺手——你的 Script 會依賴一個「上次殘留在記憶體裡、但程式碼裡根本沒有」的物件，自己跑得很順，助教跑就報錯。關掉它，強迫自己的 Script 完整。

(2) 啟用原生管線 — Code → Editing

勾選 Use native pipe operator, |> (requires R 4.1+)。

理由：這樣 Cmd+Shift+M 插入的會是 R 內建的 |> 而不是 magrittr 的 %>%。兩者在本課用途上幾乎等價，但 |> 是語言內建、不依賴套件，教材全程使用它。

(3) 開啟軟換行 — Code → Editing

勾選 Soft-wrap R source files。

理由：質詢文本一筆動輒六百字，沒有軟換行時你得一路往右捲。

(4) 確認編碼為 UTF-8 — Code → Saving

在 Default text encoding 按 Change… 選 UTF-8。

理由：這是中文資料的生死線。macOS 的預設通常已經是 UTF-8，但請親眼確認一次。編碼設錯的症狀是中文變成 \u5b78 或一堆問號，而且往往在你已經做了一堆分析之後才發現。

(5) 打開診斷提示 — Code → Diagnostics

勾選 Show diagnostics for R 以及 Warn if variable used has no definition in scope。

理由：RStudio 會在你打錯變數名或少一個括號時，在行號旁邊畫紅色驚嘆號。對零基礎的人來說，這能攔掉一半以上的低級錯誤。

(6) 顯示行號與空白 — Code → Display

勾選 Show line numbers（通常預設已開）與 Show whitespace characters。

理由：行號是你跟別人討論程式碼的座標；而顯示空白字元，在處理「被 沒 收」這種漢字間夾空白的髒資料時，能讓你直接看見問題。

▍順手可調

Appearance 分頁可以改主題與字體。中文顯示建議挑等寬中文字體避免對不齊。這項純屬舒適度，不影響正確性。

▍Windows 差異

設定入口是 Tools → Global Options…，沒有 macOS 的 RStudio → Settings 路徑。所有快捷鍵把 Cmd 換成 Ctrl。另外 Windows 的預設編碼可能不是 UTF-8，第 (4) 項對 Windows 使用者特別關鍵，務必手動確認。

Project 工作流與檔案結構

本章目標：學會用 RStudio Project 管理這門課的所有檔案，並徹底戒掉 setwd()。

本頁章節
工作目錄是什麼為什麼不要用 setwd()建立你的課程 Project資料夾結構here 套件動手練習本章小結

1. 工作目錄是什麼

R 在任何時刻都「站在」某個資料夾裡，那個資料夾叫工作目錄（working directory）。當你寫 read_csv("質詢.csv")，R 就是去工作目錄裡找這個檔名。找不到就報錯：

R Console
getwd()   # 我現在站在哪裡
list.files()  # 這個資料夾裡有什麼

新手 90% 的「檔案讀不進來」都是這個問題：R 站的位置跟你以為的不一樣。getwd() 和 list.files() 這兩行是排查第一步，請記起來。

2. 為什麼不要用 setwd()

網路上的舊教學會教你在 Script 開頭寫：

R · 請不要這樣做
setwd("/Users/yourname/Documents/text-as-data/data")   # macOS
setwd("C:/Users/yourname/Documents/text-as-data/data") # Windows

這行在你的電腦上完全正常，但它讓你的程式碼只能在你的電腦上跑。助教拿到你的作業，第一行就失敗，因為他的電腦裡沒有 /Users/yourname/ 這個路徑。這門課的 Lab 透過 GitHub Classroom 繳交、期末要附可重現儲存庫，setwd() 等於在可重現性上自己開一槍。

正確做法是使用 RStudio Project：當你透過 .Rproj 檔開啟專案時，RStudio 自動把工作目錄設在專案資料夾。你的程式碼裡只出現相對路徑（data/質詢.csv），誰拿到都能跑。

3. 建立你的課程 Project

選單 File → New Project… → New Directory → New Project，資料夾名稱建議 text-as-data-lab，位置放在你習慣的地方。

建好之後你會發現三件事：RStudio 重新啟動了一次、右上角出現專案名稱、資料夾裡多了一個 text-as-data-lab.Rproj 檔案。以後開這門課的東西，就是雙擊那個 .Rproj 檔，而不是單獨打開某個 .R 檔。

▍.Rproj 檔裡有什麼

它是純文字檔，記錄這個專案的設定（編碼、縮排、是否還原 workspace 等）。你不需要編輯它，但它會被 Git 一起管理，讓協作者拿到同樣的專案設定。

確認一下：專案開啟後在 Console 打 getwd()，回傳的應該正是專案資料夾。

「output 裡的東西全部能重新生成」這條紀律背後有個判斷標準：如果你把 output 資料夾整個刪掉，再從頭執行 R 資料夾裡的腳本，應該能得到一模一樣的結果。做得到，你的分析就是可重現的；做不到，表示有某個步驟你是手動做的而沒寫進程式碼——那正是期末繳交時會出事的地方。

5. here 套件

專案內的相對路徑已經解決了大部分問題，但有一個例外：Quarto 報告放在 report/ 子資料夾裡，render 時的工作目錄是該 .qmd 所在的資料夾，於是 data/質詢.csv 就找不到了。

here 套件解決這件事——它永遠從專案根目錄算起，不管你的檔案放多深。

R
library(here)
here()                       # 專案根目錄在哪
here("data", "質詢.csv")     # 組出完整路徑，跨作業系統通用
# 讀檔時這樣寫：
# d <- readr::read_csv(here("data", "質詢.csv"))

注意 here("data", "質詢.csv") 用逗號分隔而不是自己拼斜線。這是刻意的：macOS 用 /、Windows 用 \，交給 here() 處理，你的程式碼就跨平台。

▍Windows 差異

Windows 路徑用反斜線 \，但在 R 字串裡 \ 是逃脫字元，必須寫成 \\ 或改用 /。這是 Windows 使用者的經典陷阱，here() 正好幫你完全避開。

6. 動手練習

  1. 建立 text-as-data-lab 專案，確認 getwd() 指向它。
  2. 建立 data／R／output／report 四個資料夾。
  3. 把教材附的 立法院質詢_第11屆.csv 複製到 data/。
  4. 執行 library(here); here()，確認回傳的是專案根目錄而不是 data 資料夾。
  5. 在 R/ 建立 01-import.R，只寫兩行並存檔（先不用管 read_csv 的細節，第 6 章會講）：
    R
    library(here)
d <- readr::read_csv(here("data", "立法院質詢_第11屆.csv"))
  6. 壓力測試：關閉 RStudio，改用雙擊 .Rproj 的方式重開，直接執行 01-import.R。如果成功，你的專案結構是對的。

7. 本章小結

  • R 永遠站在某個工作目錄裡；getwd() 與 list.files() 是檔案讀不到時的第一組排查指令。
  • setwd() 會讓程式碼只能在你的電腦上跑，與本課的可重現性要求直接衝突。
  • 用 .Rproj 開啟專案，工作目錄自動就位，程式碼裡只寫相對路徑。
  • data 只讀不改、output 全部可重新生成——這兩條紀律是期末可重現儲存庫的基礎。
  • 跨資料夾或跨平台時用 here() 組路徑。

套件管理

本章目標：分清楚 install 與 library、知道套件從哪裡來，並且能看懂三種常見的安裝失敗訊息。

本頁章節
install 與 library套件從哪裡來本課套件清單三種安裝失敗函數名稱衝突renv動手練習本章小結

1. install 與 library：一次性 vs 每次都要

這是 R 新手第二常見的混淆（第一名是 Console 與 Script）。

install.packages("quanteda") 是下載安裝到硬碟，一台電腦做一次就好，之後永遠都在。

library(quanteda) 是把已安裝的套件載入這次的 R 工作階段，每次重開 R 都要再做一次。

用手機比喻：install 是去 App Store 下載，library 是點開那個 App。你不會每次用 App 都重新下載，但每次用都要點開。

▍寫進 Script 的規則

library() 寫在 Script 開頭，install.packages() 不要寫進 Script。理由：別人執行你的 Script 時，不該被強制安裝或升級套件。需要說明相依套件時，寫成註解或放在 README。

2. 套件從哪裡來

本課的套件有三個來源，安裝方式不同。

GitHubremotes::install_github("davidycliao/flaiR")開發者直接發布，沒有 CRAN 審查，通常是最新版或 CRAN 上沒有的套件。本課教師的 flaiR、legisTaiwan 都在這裡。需要從原始碼編譯。
原始碼R CMD INSTALL 資料夾最後手段。當套件原始碼需要修改才能編譯時使用（例如下方的 jiebaR 案例）。

4. 三種安裝失敗訊息

套件裝不起來是必然會遇到的事。重點不是避免它，而是能讀懂訊息、判斷是哪一種問題。以下三種涵蓋你這學期八成的狀況，第三種是撰寫本教材時真實遇到的案例。

(A) 套件根本不存在或打錯字

R Console
Warning message:
package ‘quantedaa’ is not available for this version of R

先檢查拼字。拼字沒錯的話，表示 CRAN 上沒有適用你這個 R 版本的版本——可能是套件已下架、或作者尚未跟上新版 R。解法：去 CRAN 查該套件狀態，或改從 GitHub 安裝。

(B) 缺少系統相依

R Console
configure: error: libgit2 not found
ERROR: configuration failed for package ‘gert’

這不是 R 的問題，是作業系統缺少某個函式庫。關鍵字是 configure: error 加上一個聽起來像系統套件的名字。macOS 的解法是在終端機（不是 Console）執行 brew install libgit2，Windows 則多半是缺 Rtools。

(C) 編譯失敗：真實案例 jiebaR

2026-09-17 在 R 4.6.1 安裝中文斷詞套件 jiebaR 時，CRAN 回報「not available for this version of R」（情況 A），改從 GitHub 安裝後出現：

R Console
../inst/include/lib/limonp/StringUtil.hpp:88:60: error:
    no member named 'not1' in namespace 'std'
make: *** [RcppExports.o] Error 1
ERROR: compilation failed for package ‘jiebaR’

這是套件原始碼本身跟不上時代：std::not1 是 C++ 標準在 C++17 移除的功能，而 R 4.6 預設用 C++20 編譯。不是你的電腦壞了，也不是你裝錯，是上游套件的程式碼過時了。

可行的處理方式是下載原始碼、把那兩行改寫成現代的 lambda 寫法，再用 R CMD INSTALL 手動安裝——這也是前面表格裡「原始碼」那一列存在的理由。如果你遇到這個錯誤而不想自己改原始碼，替代方案是改用 Python 的 jieba（透過第 18 章的 reticulate），或先用 quanteda 內建的斷詞器處理中文，第 12 章會比較兩者差異。

▍這類問題會反覆出現

修補後的版本只存在於你自己的電腦上。日後重裝或更新同一個套件，會再撞到同一個錯，所以請把處理步驟記在專案的 README 或筆記裡。等到上游作者修正後，就能恢復用一般方式安裝。

▍為什麼要跟你講這麼細

因為這正是課綱第 10 章要教你的判斷力：看到一大片紅字時，能分辨「我打錯了」「我的系統缺東西」「這個套件本身壞了」。三種問題的解法完全不同，而新手最常見的反應是三種都用同一招——重裝——然後浪費一個下午。

5. 函數名稱衝突

載入套件時常看到這類訊息，它不是錯誤：

R Console
The following objects are masked from ‘package:stats’:
    filter, lag

意思是 dplyr 的 filter() 蓋掉了 stats 的 filter()。多數時候你要的正是後載入的那個，所以沒事。但當你確實需要指定時，用雙冒號：

R
dplyr::filter(d, 會期 == 1)   # 明確指定用 dplyr 的
stats::filter(x, rep(1, 3))   # 明確指定用 stats 的

套件::函數 這個寫法還有個好處：不用 library() 也能呼叫。教材裡偶爾出現的 readr::read_csv() 就是這個用法，目的是讓你一眼看出這個函數屬於哪個套件。

6. renv：把版本鎖起來

renv 為單一專案建立獨立的套件庫，並記錄每個套件的版本。別人拿到你的專案，執行 renv::restore() 就能重建一模一樣的套件環境。

R Console
renv::init()      # 在專案中啟用，掃描並建立獨立套件庫
renv::snapshot()  # 把目前用到的套件版本寫進 renv.lock
renv::restore()   # 依 renv.lock 還原（別人拿到你的專案時用）

要不要現在用？建議先不要。renv 會讓每個專案各自安裝一份套件，你剛裝好的 41 個套件不會自動被新專案看到，對新手是額外的困惑來源。等到期末要交可重現儲存庫時，再回來用它，那時它的價值才真正顯現。這裡先讓你知道有這個東西，以及它解決什麼問題。

7. 動手練習

  1. 在 Console 執行 library(quanteda)，觀察它印出的啟動訊息與 masked 提示。
  2. 執行下面這行，確認你的機器上關鍵套件都在：
    R Console
    pkgs <- c("quanteda", "jiebaR", "stm", "conText", "flaiR", "tidyverse")
data.frame(套件 = pkgs,
           已安裝 = sapply(pkgs, requireNamespace, quietly = TRUE))
  3. 故意製造情況 A：執行 install.packages("quantedaaa")，讀一次那個警告訊息。這是你之後會看到很多次的句型。
  4. 在右下角 Packages 面板找到 quanteda，點擊套件名稱進入說明索引，隨便點一個函數看它的文件。
  5. 執行 packageVersion("quanteda")。把版本號記下來——回報問題給套件作者時，第一件被問的就是這個。

8. 本章小結

  • install.packages() 一台電腦做一次；library() 每次開 R 都要做。後者寫進 Script，前者不要。
  • CRAN 用 install.packages()，GitHub 用 remotes::install_github("帳號/儲存庫")；本課教師的套件在 GitHub。
  • 安裝失敗分三類：打錯字或版本不合、缺系統相依（configure: error）、套件原始碼過時（compilation failed）。三種解法完全不同。
  • masked 訊息不是錯誤；需要明確指定時用 套件::函數。
  • renv 留到期末交可重現儲存庫時再用。
